# US-308 — Design name, DST export via share sheet, exported UTType, gating

**Epic**: E7 Export & sharing | **Estimate**: ~5 h | **Depends on**: US-211, US-306, US-303

**Status**: In progress — planned 2026-08-29 with `swift-architect` and `swift-ui-design`. **The planning pass corrected twelve things in the criteria below** (marked **planning correction** inline, each verified against the named source *by execution* rather than taken on report — probe artifacts were built and run, including a hosted simulator test run and a release-configuration timing measurement). Sebastian took four scope decisions, recorded under "Scope decisions". **No human Xcode session is required**, which is the story's biggest scheduling result and was not obvious before planning.

**Story**: As a user, I want to name my design and send the `.dst` file out through the share sheet, so I can get it onto an embroidery machine.

Catroid's stage-menu Share button is the exact structural analogue — gate → build the DST → hand it to the system share UI — and this story reproduces that shape while improving on essentially every detail below it. Two facts set the bar low and the value high: **Catty's shipping app exports every `.dst` with a blank `LA:` field** (only its unit tests ever pass a name), and **neither reference declares a `.dst` type at all**. So design naming and the UTType are real functionality with no working precedent on either platform.

## Acceptance criteria

- [ ] `DesignName` is a pure value type: ≤ 15 characters, ASCII only, non-empty, with the whitespace rule pinned explicitly rather than left to chance. Surfaced as a **live counter, not a post-hoc error** (Catroid silently `take(15)`s the project name and mangles non-ASCII to `?` bytes under `US_ASCII`).
  - **Planning correction 1 — the whitespace rule is decided, and the engine forced the decision.** `DSTHeader` writes `"  pad"` into the `LA` field **verbatim and never trims** (measured: input `"  pad  "` → `LA` reads `"  pad"`), and an all-spaces name is indistinguishable from an empty one in that field. The rule is therefore **trim on input, then validate**: `"  Rose  "` is valid as `"Rose"`, interior spaces stay legal, `"   "` resolves to `.empty`. Scope decision 2.
  - **Planning correction 2 — `DesignName` is a *rejecting* layer in front of a *mangling* backstop that already exists**, which the criterion does not say. `DSTHeader.sanitized(_:)` (`DSTHeader.swift:60-66`) already maps non-ASCII scalars to `_` and truncates to 15. Measured backstop behaviour: `""` → 15 spaces; `"Ünïcödé"` → `_n_c_d_`; `"0123456789abcdefghij"` → `"0123456789abcde"`; `"a/b:c"` → `"a/b:c"` (**`/` and `:` pass through the header untouched**). The backstop **stays, unchanged and `private`** — its own comment records that mapping before `prefix(15)` is what makes `LA` unable to overflow. The two layers relate as *validate-then-serialise*: the app refuses input the user can see and fix; the engine silently normalises input no user typed, so no caller anywhere — M4/M5, a `.catrobat` importer, a future CLI — can emit a 16-byte or non-ASCII `LA` field.

- [ ] The **file name is sanitised independently of the header label** — they are unrelated fields in the format. Rejects `/` and empty (Catroid's `sanitizeFileName` has no empty check and produces a file literally named `.dst`). A 15-char label with a longer file name is legal.
  - **Planning correction 3 — there is a third failure mode the criterion misses.** Measured against the real filesystem: `/` becomes a path separator (`URL.appending(path: "a/b.dst").lastPathComponent == "b.dst"`, write fails NSError 4); empty collapses to the directory (fails 512); and a **264-character name fails with NSError 514, "file name is invalid"** — there is a 255-byte `NAME_MAX` the criterion does not mention. Also measured: `.dst` alone, `Ünïcödé.dst` and `con:x.dst` all write fine — which confirms both that Catroid's empty-name bug is invisible at the filesystem layer and that **the file name may legitimately keep non-ASCII the header label cannot**.

- [ ] `UTExportedTypeDeclarations` in `Info.plist`: identifier under a domain we control (reverse DNS; **not** prefixed `public`, `dyn` or `com.apple` — Apple reserves all three), `UTTypeTagSpecification` with `public.filename-extension` = `dst`, `DST`, and a `UTTypeDescription` localised via `InfoPlist.strings`. No `LSHandlerRank` ambitions (ADR-011 — we open nothing). Structural template: Catty's `.catrobat` declaration (`App-Info.plist:102-123`), the only prior art available.
  - **Planning correction 4 — the cited template is an `UTImportedTypeDeclarations` entry, not an exported one**, and it lists `public.data`/`public.archive` with no `public.content`. Accurate as a *structural* template only; the criterion should say "imported", so that the exported-vs-imported tension two criteria down reads correctly.
  - **Planning correction 5 — `InfoPlist.strings` is superseded.** An **`InfoPlist.xcstrings`** created on disk in the synchronized folder is picked up and compiled with **no project-file change**: verified by building, which produced `catrobat_embroidery_ios.app/en.lproj/InfoPlist.strings` carrying the resolved value, with `UTType(id)?.localizedDescription` returning it. Same mechanism, Crowdin-friendly, consistent with `Localizable.xcstrings`, and — unlike a `.strings` file — it has somewhere to put the translator comment every other user-facing string in this repo carries.

- [ ] **`UTTypeConformsTo` lists `public.data` *and* `public.content`.** `public.data` is what lets Finder and the Files app represent a stored item at all; `public.content` is what Apple documents as the conformance that **allows sharing over AirDrop** — and this story exists to share the file, so omitting it would break the headline use case on the most likely destination. (Found in Apple's "Defining file and data types for your app" while checking the finding below; an earlier draft listed `public.data` alone.)
  - **Scope of what was verified.** Both conformances were confirmed to *resolve* on a hosted simulator run (`conforms(to: .data)` and `conforms(to: .content)` both true). The **causal** claim — that `public.content` is what enables AirDrop — is Apple's documentation as quoted, not something this planning pass measured. It moves to the manual pass, and needs two devices.

- [ ] Record the exported-vs-imported tension rather than silently resolving it: Apple's guidance says define an *exported* type when your app is "the canonical source of information for that type", and an *imported* type for "a proprietary file format the system doesn't declare" — Tajima DST is the latter, but the imported path also says to reuse the originator's identifier, and no declared DST identifier exists. ROADMAP.md:57 already pinned "exported", the practical difference is Launch Services ranking that ADR-011 does not want, so exported stands — with the reasoning written down.
  - **Planning correction 6 — the citation has drifted.** The pin is at **`ROADMAP.md:63`** ("share-sheet export with an **exported UTType for `.dst`**"), not `:57`, which is now the M3 scope paragraph. The pin itself stands.

- [ ] `DSTDesign: Transferable` with `FileRepresentation(exportedContentType:)`, shared via SwiftUI `ShareLink` — which gives iPad popover anchoring and activity exclusions for free, replacing Catty's manual `UIActivityViewController` plumbing.
  - **Planning correction 7 — `DSTDesign` and its identifier must be `nonisolated`.** The project sets `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (pbxproj:297, 357, 389, 421) and the test target inherits it, while `Transferable.transferRepresentation` is a **nonisolated static** requirement. A probe failed to compile with *"main actor-isolated let 'dstID' can not be referenced from a nonisolated context"* until both the struct and the identifier constant were marked `nonisolated`; the injected writer protocol must be `Sendable` for the same reason. Verified spelling: `nonisolated` on the struct and on a file-scope `let`. (`nonisolated static let` inside a `UTType` extension was **not** verified — prefer the verified spelling.)

- [ ] **The Info.plist declaration needs a test that actually consults the type database.** `UTType(exportedAs:)` *declares* a type your app owns; it does not look one up, so it neither validates the plist nor fails when the declaration is missing. The canary must therefore use the **failable lookup** `UTType("<our identifier>")` and require non-nil — that is the initializer that resolves against declared types. (An earlier draft asserted `UTType(exportedAs:)` "traps at runtime if the identifier is not declared" and proposed it as the canary; the claim was unverified and the test could not have caught the wiring failure it was written for — Codex round 3, confirmed against Apple's documentation.)
  - **Planning correction 8 — the trap is broader than the retraction states, and the canary is now proven rather than argued.** `UTType(exportedAs: "org.example.nope.zzz").isDeclared` is **`true`** for a completely undeclared identifier (and `.conforms(to: .data)` is `false`), so *any* assertion built on `UTType(exportedAs:)` — `.isDeclared` included — passes with the plist entry missing entirely. Pinned as its own regression test so nobody re-invents it. The lookup canary was then **proven red and green**: with the declaration present all thirteen probe tests passed on `iPhone 17` / iOS 26.5; with `Info.plist` emptied back to `<dict/>` and re-run on the same simulator, **six flipped to failing**, including the lookup — no stale-LaunchServices false pass, even immediately after the same bundle ID had been installed *with* the declaration.
  - **Planning correction 9 — the canary can only ever be a *hosted app* test.** The same probe run as a bare macOS executable, and again from inside a hand-built `.app` carrying the declaration in its own `Info.plist`, returned **nil** both times: the declaration resolves only once LaunchServices has *registered* the bundle, which simulator installation does and a direct exec does not. The test target is hosted (`TEST_HOST`/`BUNDLE_LOADER`, pbxproj:431, 444, 451, 464), so this works — but it could never have been an SPM test, and that is worth pinning before someone moves it there for speed.
  - **Addition — a second, mechanism-independent canary.** `Bundle.main.infoDictionary?["UTExportedTypeDeclarations"]` structure (identifier, both conformances, both extension tags), which does not consult the type database at all. Verified to fail correctly in the negative run. One line each, and it survives any future change in how LaunchServices resolves.

- [ ] Export goes through an injected `DSTFileWriting` interface (ADR-006 pattern 2) that calls `DSTFile.write(to:)` — the package's only I/O. **The app writes no bytes itself.** The temp file is cleaned up (Catty never cleans up). This is Catty's proven `shareDST(embroideryService:)` + `EmbroideryServiceMock` shape, which is the one thing in that file worth porting.

- [ ] **Gating is `exportModel.count > 1` on the post-replay assembled stream**, not `hasValidPattern` (which counts recorded *ops* the replay may reject) and not the display-list count (op-derived, same defect). This closes the divergence ADR-020 left "for whoever wires up export to decide" and matches Catroid's `validPatternExists()`, which counts points in the *built* streams.
  - **Planning correction 10 — "exportable" is unreachable mid-run, and the criterion does not say so.** `PreviewRunState.exportModel` (`PreviewRunState.swift:53`) is written **only** in the `if let termination` branch of `apply(_:)`, and `clear()` resets it to `nil` from both `begin()` and `reset()`. Driven frame by frame: `exportModel == nil` at every frame of a running run, becoming `Optional(3)` only after `stop()`. So the share affordance is **disabled for the entire duration of every run**, and can become enabled only by the run ending — naturally, at the cap, or by Stop. This needs a **third disabled-hint reason the story never lists**: "still stitching — stop or wait for the run to finish". Without it a VoiceOver user mid-run is told about the wrong situation. It also means "export the design you can see, right now" is not something the app offers in M3; ADR-026 says so, so a later story does not read it as a defect.

- [ ] **The export gate and the render empty-state may legitimately disagree**, and the app says so specifically. Catroid keeps one predicate for both so they agree by construction; for us they diverge exactly in ADR-020's rejected-coordinate case — ops recorded and drawn, every one rejected at replay. When they disagree the message is "nothing in this design can be embroidered", not a header-only file. Catty ships a valid-looking 515-byte header-plus-EOF file with zero stitches; we do not.
  - **Verified, with the numbers.** The story's literal program (`placeAt(1e300, 0)` then `stitch`) gives display list 1, assembled stream **0**; two such stitches give 2 and 0; `stitch` alone at the origin gives 1 and 1. The mechanism is `Interpreter+Step.swift:255` — `emitStitches` appends `.stitch` unconditionally, *after* `manager.addStitch` has silently refused the point. The 515-byte figure is also exactly right: an empty stream serialises to **515** bytes and a one-stitch design to **518**.
  - **Planning correction 11 — the divergence is already proven by an engine test, so this story must not re-prove it.** `adr020RejectionIsAFifthDivergence` (`StagePreviewTests/DisplayVersusExportModelTests.swift:148`) already uses the exact program and asserts `list.count == 2, stream.count == 1`. US-308's test is therefore about **the gate's verdict**, not the divergence — otherwise it duplicates a green test, which is this repo's named failure mode.
  - **Planning correction 12 — the criterion's implied picture is wrong.** The rejected coordinate is *finite*, so `StitchDisplayList.append`'s finiteness rule admits it (measured bounds `minX: 1e300 … maxX: 1e300`). In the pure-rejection case the canvas draws a **degenerate one-point design at an absurd offset** — visually near-empty. The message is doing real work, but this is not the reassuring "you can see your design, it just can't be sewn" that the wording implies.

- [ ] `ExportState` is `idle | preparing | ready(URL) | failed(ExportError)`. This is where the roadmap's `failed` case actually belongs — US-306 explains why the *run* has none.
  - **Planning correction 13 — `preparing` is dropped; the enum is three cases.** Measured in **release** configuration: building a `DSTFile` from a 52 240-stitch stream takes **2.6–3.0 ms** and writing it **0.47 ms** — so at the milestone's own exit-criterion size the whole export is under 4 ms, a state no user can perceive, and it is *testably* reachable only by injecting a gated writer double. This is the same shape as the ROADMAP's own correction striking `failed` from the **run** enum for having no producer, and as ADR-028's deletion of an unreachable accessibility hint rather than sending it to ~75 Crowdin translators. Scope decision 3.
  - **Planning correction 14 — `ExportState` and `ShareLink` are in tension, and only one shape satisfies both criteria.** A `ShareLink` owns preparation inside its own `FileRepresentation` closure and reports failure to the *system* share UI, so `.preparing` and `.failed` would have no view consumer and `.ready(URL)` would never be rendered. A second, independent constraint forces the same conclusion: **`Transferable.exported(as:)` — the only way a test can drive the representation — is iOS 18.2+** (verified as a compile error against our iOS 17 target), so a write happening *only* inside that closure makes test item 3 unbuildable at the deployment target. Resolution: **eager preparation.** `ExportViewModel.prepare()` builds the `DSTFile` and calls the injected writer, reaching `.ready(url)`; the `FileRepresentation` closure only returns `SentTransferredFile(url, allowAccessingOriginalFile: false)` for a file already on disk. `prepare()` runs on run **termination** (a `ShareLink` needs its item at construction time) and re-runs on **name commit** (`onSubmit`/focus loss, never per keystroke), because the name is in the `LA` **bytes**, not just the filename.

- [ ] US-211's overflow errors surface as a specific localised message naming the limit, with the design still on screen and still resettable. Not `print("File could not be written!")`, which is Catty's actual error handling.
  - **Planning correction 15 — the overflow is a *gate reason*, not an export failure.** If the throw happens inside the `Transferable`, the user sees the system's generic share failure and this criterion's localised string is **unreachable**. It must come from a **pre-flight `DSTHeader` build** — complete and cheap, because `DSTFile.swift:26-28` and ADR-025 both state that only the header can fail, and it is the *engine's* rule rather than a re-derivation of it. Conveniently it is also name-independent: `LA` cannot overflow, so a keystroke never changes the overflow verdict.
  - **Note on the message table.** `DSTHeader.Field` has twelve cases and the switch must be exhaustive, while `Field.limit` is documented as *meaningless* for six of them (`DSTHeader.swift:145-155`). The six unreachable fields route to one generic message: shipping six invented nouns would repeat the mistake ADR-028 had to undo, and trapping would repeat the one ADR-025 removed.

- [ ] **Story-specific definition of done**: the name field's counter moves below the field at AX1 rather than truncating; the share affordance's disabled state carries a localised `.accessibilityHint` saying *why*; export success is **not** haptic (M6 owns the haptic map).
  - **Planning correction 16 — `ViewThatFits` cannot build the AX1 rule.** A `TextField` is horizontally greedy with no meaningful ideal width, so the horizontal candidate either always fits or never does. The switch must be driven by a *value*: `DesignNameFieldLayout.axis(for: DynamicTypeSize)`, applied as `AnyLayout(...)` — `AnyLayout` rather than `if`/`else`, because the latter builds two different view trees, so a Dynamic Type change while the field is focused would destroy the `TextField` and dismiss the keyboard. Putting the *policy* in a pure function is also what makes it assertable, the same mitigation ADR-028 used for Reduce Motion. Threshold arithmetic: at AX1 on a 393 pt compact width, "14/15" at scaled caption is ≈ 55 pt, leaving ≈ 298 pt of field — about twelve characters of 28 pt text, so a 15-character name truncates. That is the truncation this criterion forbids.
  - **Planning correction 17 — "not haptic" means adding nothing, and something still fires.** `StageView.swift:95-101` already carries `.sensoryFeedback(trigger: runState)` emitting `.stop` when a run finishes — and since the share affordance becomes enabled at exactly that instant, the user *does* feel something at export-ready time. It comes from US-306's transport haptic, not from export. Stated so a reviewer does not read it as a violation.

- [ ] Close-out pins **ADR-026**: the gating rule, the UTType identifier, the temp-file policy, and the design-name rules.
  - Confirmed reserved: `docs/DECISIONS.md` jumps 025 → 027.

## Scope decisions (Sebastian, 2026-08-29)

1. **UTType identifier: `org.catrobat.embroiderydesigner.dst`** — matches `PRODUCT_BUNDLE_IDENTIFIER` (pbxproj:385) and Catty's house style (`org.catrobat.pocketcode.catrobat`), and verified working end to end. Chosen over the shorter `org.catrobat.dst`, which would claim the type on behalf of the whole organisation from a thesis project before the transfer.
2. **`DesignName` whitespace: trim on input, then validate.** Interior spaces stay legal; `"   "` resolves to `.empty`. Chosen over rejecting leading/trailing whitespace, because trailing spaces are invisible in a text field and the error's cause would be unseeable.
3. **`ExportState` drops `preparing`** — three cases, on the 3 ms measurement above.
4. **Temp files: a per-session UUID directory** under `URL.temporaryDirectory`, one file inside, rewritten on each `prepare()`, the directory removed on `RunViewModel.reset()`. `allowAccessingOriginalFile: false` means the system copies the file, so deleting ours cannot break a share in flight.

Three further decisions taken at planning and open to reversal on review:

5. **The name field seeds from `SampleID.resourceName`, not `sample.displayName`.** `displayName` is a `LocalizedStringResource` from the `Samples` bundle (`SampleProgram.swift:52-58`) and "Octagon Rosette" is **exactly 15 characters** in English — so any locale whose translation is one character longer, or not Latin at all, would open the screen already in a validation error the user did not cause. `resourceName` (`SampleID.swift:23-28`) gives "OctagonRosette" (14) and "SquareCoil" (10): ASCII, locale-independent, and already the canonical file stem. Recorded because it reuses a **persistence token** as a default machine label — defensible precisely because `LA` is a machine label rather than UI copy.
6. **`DSTFile.init` gains no `DesignName` overload; the app passes `String`.** Measured ripple for changing the signature: `DSTFile(` at **28** sites across 13 files and `DSTHeader(` at **29** across 8 — **56 call sites across 20 files**, larger than US-211's 41-across-15. A *new overload* would cost zero ripple and is still declined, because making the two layers agree by construction is exactly what this story does not want: it would render `sanitized` unreachable and lose the property that a direct engine caller still cannot produce a malformed `LA` field. ADR-026 must therefore state that the package ships a validator its own serialiser does not require — deliberately, as shared vocabulary rather than a precondition — or a future reader will "tidy" it into the initialiser and pay the 56-site ripple.
7. **`StageView` gets a third forced extraction.** It is at 327 lines against SwiftLint's hard 400 under `--strict`, and two prior extractions (`StageTransportRow`, `StageCanvas`) both record this same ceiling as their cause. The caption/notice block (`StageView.swift:195-294`, ~100 lines) moves to `StageNotices.swift`, leaving ~272.

## Test-first plan

Engine tests run under `cd Packages/EmbroideryEngine && swift test`; app tests need the simulator. **Two items below cannot be red** and are labelled characterisation tests, so the `[red]` commit's failure list is honest.

1. `DesignName`: 15 chars accepted, 16 rejected with the count surfaced, non-ASCII rejected naming the offending character, empty rejected; the whitespace decision (scope decision 2) pinned by a test.
   - Assert the **payload**, not just rejection: `.tooLong(count: 16, limit: 15)`, `.nonASCII(character: "ü")`, `.empty`. Asserting only "is nil" passes against a validator that rejects everything.
2. File-name sanitisation is independent of the header label; `/` and empty rejected; a 15-char label with a longer file name is legal. **Plus the 255-byte `NAME_MAX` cap** found at planning.
3. A recording `DSTFileWriting` double receives the expected `DSTFile` and file name; a throwing double produces `.failed` with the error surfaced and the design intact on screen.
   - **Buildable only because `prepare()` calls the writer from a method.** If implementation drifts to writing only inside the `FileRepresentation` closure, this item silently becomes untestable at iOS 17 — a "test that could not fail" arriving through an availability boundary rather than a bad assertion.
4. Gating: 0 or 1 assembled stitches → not exportable; ≥ 2 → exportable. **And the divergence case**: a program whose every coordinate is rejected (`placeAt(1e300, 0)` then `stitch`) is not exportable even though the display list is non-empty.
   - The ≥ 2 case (`octagonRosette`, 3 194 stitches) is **what stops the 0 and 1 cases being satisfied by a constant** — do not ship them without it. The 1-stitch case must assert `exportModel?.count == 1` *first*, or its verdict is accidental. The divergence case must reach a **distinct** verdict from the zero-stitch case, or the enum is not carrying the distinction the criterion is about.
   - **Plus**: mid-run is never exportable — `exportModel == nil` and the verdict is "not run" at every frame of a gated run.
5. ~~Export after `.stoppedByUser` produces byte-identical output to export at the same point of a completed run~~ — **planning correction 18: not constructible as written.** `InterpreterDriver.completionReason` orders completion **before** cancellation, so a single program can never yield `.stoppedByUser` *at* the point it would also have completed; "the same point of a completed run" cannot mean the same program. The buildable version, run end to end with the existing `GatedRunPacing` double (`StagePreviewTests/RunDriving.swift:118`), is a **twin-program pair**: program A is `placeAt`/`stitch` ×3 then `forever { wait(1/60) }` — all stitching done, then parked in a loop that emits nothing and cannot terminate — stopped after the third stitch; program B is the same three pairs with no loop, driven to natural completion. Measured: both `count == 3`, `DSTFile(...).data` byte-identical.
   - **It is vacuous on its own**, because the two streams are *equal* and `EmbroideryStream` is `Equatable`, so the byte comparison adds nothing. It needs three further guards: `stopped.count == 3` (a nil or empty export model makes any "identical" claim trivially true), `stopped == assembledStream(of: completedProgram)` via the existing helper at `RunDriving.swift:93` — the same device Codex round 3 forced on US-306 — and the header's `ST` field reading `"3"`, i.e. the file describes the *partial* design rather than a stale count.
   - Lives in `StagePreviewTests`: app tests cannot import a package test target, and that target already depends on `EmbroideryEngine`, so `DSTFile` is reachable.
   - **Planning correction 19, found at implementation rather than at planning: the corrected item is *already green*.** Once written, `ExportAfterStopTests` produced no compile errors at all — it uses only API that already existed — and it was then run with **every one of US-308's new production files removed** (`ExportEligibility.swift` and its tests moved aside): both tests passed. So the byte-identity property is not something this story builds; it already follows from US-306's design (`stop()` cancels the producer only, and the terminal update carries `assembledStream()`) plus `EmbroideryStream: Equatable`. The suite ships as a **characterisation and regression guard** — it pins the Catty teardown hazard shut and pins the `ST` field to the partial design — and is explicitly **not** counted as red-phase work. This is the fourth consecutive story to find an already-green test item, and the first to find one only after writing it; the cheap check that catches the class is "does the new test file reference any symbol this story adds?"
6. A US-211 overflow (100 colour blocks) produces the specific error rather than a trap.
   - **Split into 6a and 6b at planning.** *6a, engine*: emission order is `LA, ST, CO, …`, so `ST` is checked **before** `CO` — harmless for a small design, verified: 100 blocks over 100 stitches gives `ST = "100"` (limit 999 999, fine) and throws `fieldOverflow(field: .colorBlocks, value: "100", limit: 99)`. The **99-block control must not throw** (measured: 812 bytes) — asserting only "throws" passes against a build that throws on everything, and US-211's own lesson is that for a typed-error story the exit assertion is the `.success` case. *6b, app*: given a constructed `fieldOverflow(field: .colorBlocks, value: "100", limit: 99)`, the view model lands in `.failed` and renders a localised message containing `99`.
   - ADR-028's standing instruction applies: **do not source the number from `StageSummary.colorCount`**, which counts display colour runs rather than `colorChangeCount + 1`.
7. **Info.plist wiring canary**: in the app test target, the failable lookup `UTType("<our identifier>")` is non-nil, and the resolved type conforms to both `public.data` and `public.content` and claims the `dst` extension. Must be the *lookup* initializer — `UTType(exportedAs:)` constructs a type from an identifier without consulting the declaration, so a test built on it passes with the plist entry missing entirely.
   - Verified capable of failing: six of thirteen probe assertions flip red with the declaration removed. Plus the structural canary over `Bundle.main.infoDictionary`, and the `UTType(exportedAs:)` trap pinned as a **characterisation** test (already true, not a red-phase item).
8. **Manual**: the exported file opens in Ink/Stitch with the expected `LA:` name and the expected colour stops.
   - Concretely: generate one `.dst` from `squareCoil` (`CO = 2`, so there is a real colour stop to inspect) with a 15-character name, and one with a name the backstop *would* mangle if `DesignName` were bypassed; confirm the name reads exactly as typed, one colour stop at the expected point, and no warnings on open. Plus one AirDrop test to a Mac, since the `public.content` justification is the AirDrop path and planning could verify the conformance but not the behaviour.
9. **Characterisation (cannot be red)**: `DSTHeader`'s sanitisation is unchanged — the five measured rows above, asserted on the `LA` bytes. Guards the backstop against a later "tidy" that collapses it into `DesignName`.

## Placement

Decision rule: rules that come from **the DST format or the filesystem**, with no localised copy and no I/O, go in the package under `swift test`; rules that come from **UX, state, localisation, Observation, SwiftUI or I/O** go in the app. **No new package target or product is needed**, which is why no Xcode session is.

| Type | Home |
|---|---|
| `DesignName`, `DSTFileName` | `Sources/EmbroideryEngine/` — their rules are the `LA` field's and the filesystem's |
| `ExportEligibility` (the gate) | `Sources/StagePreview/`, computed over `PreviewRunState` — a pure function of `exportModel` and `display`, both of which live there |
| `DSTFileWriting`, the real writer | app — the I/O seam (ADR-006 pattern 2) |
| `ExportState`, `ExportError`, `ExportControl`, `ExportViewModel`, `DSTDesign` | app |
| `StageNotices`, `DesignNameField`, `StageExportRow` | app (scope decision 7) |
| `InfoPlist.xcstrings` | app, beside `Localizable.xcstrings` |

Two lint items this story must handle: `.swiftlint.yml:58`'s `localized_user_facing_strings` name list does **not** include `ShareLink` or `SharePreview`, so a literal title would sail past the rule — both names get added here. And the sibling rule at `.swiftlint.yml:85` already names "a design name the user typed" as the legitimate `Text(verbatim:)` case, so the field's echo of the user's text passes as long as it is bound to a value.
