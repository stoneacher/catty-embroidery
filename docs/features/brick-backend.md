# Brick backend

**Status**: In review — PR 1 (slices 0–3) merged as #71; PR 2 (slices 4–7) is #72, awaiting the Codex loop and Sebastian's Ink/Stitch check | **Epic**: E8 (+ E3 formulas, E5 thin) | **Branches**: `feature/brick-backend` (PR 1), `feature/brick-backend-paths` (PR 2)

**Goal**: a program can draw arcs and quadratic curves (Catroid's **Arc** and **GoThrough**), and its formulas can use Catroid's math functions and the object's own x, y and direction. Preview and `.dst` export behave as the Android Embroidery Designer does wherever Catroid is sound, and every divergence is pinned by a named test.

Arc and GoThrough are the only bricks of Catroid's Embroidery category still missing here (`CategoryBricksFactory.kt:1039-1056` appends `setupPeripheralMotionBrickList()`, `:1080-1094`). They join our `.motion` palette group after `pointInDirection`.

**In scope**
- `Brick.arc(direction:radius:degrees:)` and `Brick.goThrough(throughX:throughY:x:y:)`, executed, previewed and exported.
- Formula functions: `sin cos tan arcsin arccos arctan arctan2 sqrt abs round floor ceil ln log exp pi min max mod`.
- Formula sensors: `objectX objectY motionDirection`.
- Thin app wiring: palette entries, row sentences, symbols/tints, a left/right control for Arc, number fields for GoThrough, locked display of function and sensor formulas.
- One bundled sample using Arc, GoThrough and functions (decided 2026-10-17), so the feature is visible in the app and Ink/Stitch has a real design to check.

**Out of scope** (each deliberate)
- **`rand`** — deferred (decided 2026-10-17). Evaluation is pure, Catroid's integer-vs-decimal rule needs the literal's spelling (`Formula.number(Double)` drops it), and it costs byte-exact tests. Recorded design for later: a seeded generator stored inside `Interpreter`, seed injected per run.
- **Authoring functions or sensors in the UI.** There is still no formula editor (ADR-040); these formulas are shown locked with a reason. They reach a program through files, Swift-built samples and the planned language-test runner. Not a defect.
- Catroid's `power()` function (`^` exists, with ADR-017's pinned semantics), `true`/`false`, comparisons, logic, and the control bricks If/IfElse, RepeatUntil, WaitUntil, ForVariableFromTo — the **Variables** feature.
- Other sensors; GlideTo, GoTo, PointTo, IfOnEdgeBounce (not in Catroid's Embroidery category).
- The engine's `javaRound` (`Geometry.swift:16`, `floor(x + 0.5)`) differing from Java 7+ `Math.round` at 0.49999999999999994 and near 2^52: sub-resolution for coordinates (ADR-019 class), so it goes to the backlog together with a correction note on ADR-012's wording. The **ROUND function** implements Java 7+ semantics from the start.

**Brief review**: done 2026-10-17 — one Codex round, 7 findings (1 High, 5 Medium, 1 Low), all valid, all folded into this brief (journal). The High: Catroid gates the stitch feed on its stored `Float` position, which the first draft's `Double` gate did not match; now a pinned divergence (D5).

## Decisions taken at planning (2026-10-17)

Planned with `swift-architect`; the math premises were probed in Swift and `jshell` (desktop JDK 17, not Android ART — hence tolerance except at ADR-019 thresholds).

- **D1 Formula representation — per-arity cases** in `ProgramModel/Formula.swift`: `unaryFunction(UnaryFunction, Formula)`, `binaryFunction(BinaryFunction, Formula, Formula)`, `constant(FormulaConstant)`, `sensor(Sensor)`. Arity is type-enforced (no runtime arity admission, no new `ProgramDocumentError`); synthesized Codable follows `binary`'s existing shape; case names mirror Catroid's `Functions`/`Sensors` so the code.xml importer maps 1:1.
- **D2 Function semantics — mirror Catroid, four pinned divergences.** Trig in degrees (`x · π/180`), inverse trig returns degrees, every result through the existing per-node `normalize` (`exp(1000) → MAX`, `ln(0) → −MAX`), NaN at the root throws (`sqrt(-1)`, `arcsin(2)`). Mirrored: `x mod 0 = x`; `round` is Java 7+ `Math.round` including **NaN → 0** and Long saturation; `min`/`max` return NaN if either argument is NaN (hand-written — both Swift spellings disagree with Java). Divergences:
  - (a) `mod` is the floored modulo: fixes Catroid's `6 mod −3 = −3` (here 0) and its non-terminating loop for `mod(-1e300, 1)`.
  - (b) `arctan2(0, 0) = 0` where Catroid returns a random angle; this also hides IEEE's `atan2(0, −0) = 180`.
  - (c) ±1 ulp libm differences, as in ADR-014.
  - (d) `round` follows Java 7+, not the engine's `javaRound`.
- **D3 `rand` deferred** (see out of scope).
- **D4 Sensors without breaking ADR-042.** `Scope` gains `func value(of sensor: Sensor) -> Double` (explicit, no default). `VariableScope` returns 0; `VariableStoreScope` carries a `VirtualNeedle` snapshot from `scope(forObjectAt:)`. `motionDirection` is folded to (−180, 180] at the read (`VirtualNeedle` keeps its (−360, 360) representation, `VirtualNeedle.swift:95`). The scope is built before `needle.apply` (`Interpreter.perform` builds it, then `performMotion` applies): sensors read the needle *before* the brick moves it.
- **D5 Arc and GoThrough execution.** One `.brick` instruction, **one tick** (ADR-018; Catroid's duration is 0). Geometry lives in `VirtualNeedle` (`arc(radius:sweepDegrees:)`, `goThrough(through:destination:)` → `[NeedleUpdate]`). Direction becomes a signed sweep (LEFT positive); radius is `abs`. Samples **i = 1…100** (Arc's i = 0 is a 1-ulp float/double artefact in Catroid that can turn a 0° arc's heading arbitrarily). **Degenerate guard first** (Codex brief review, finding 2): `radius == 0` or `sweep == 0` emits one unchanged update with the heading unchanged, before any sample is computed — skipping i = 0 alone is not enough, because at sweep 0 every sample reconstructs the start through `centre + r·(cos, sin)` with a binary64 residual (start (0.1, 0.2), heading 33°, r = 10 is off by ~1e-15). **Feed and heading rule**: a sample whose `Double` position differs from the previous sample's (the needle's, for i = 1) sets the heading to that chord and is fed to the pattern and emitted as `.needleMoved`; if none is fed, one unchanged update is emitted (US-204's rule for turns). The heading half is exactly Catroid's (`ArcAction.kt:86-96` compares theoretical `Double` samples). **The feed half diverges, pinned** (Codex brief review, finding 1): Catroid feeds only when the `Float` it stores in `Look` changes (`Look.java:310, 452`), we feed when the `Double` sample changes. They differ only where `Float` spacing exceeds the chord — e.g. start (2^30, 2^30), heading 0, arc left r = 20, 90°, running stitch 10: Catroid's look never moves and stitches nothing, we move (−20, +20) and stitch. This is ADR-014's accepted float-vs-Double divergence reaching the motion layer, where the needle has always been `Double`; ADR-047 states it, and a named byte-visible test pins our side. **Compute, then commit**: any non-finite sample makes the brick a no-op; a bad formula is catch-and-skip like `moveNSteps`, not Catroid's teleport-to-origin accident (`ArcAction.kt:50-77`). `VirtualNeedle.apply(_:scope:)` returns `[NeedleUpdate]?` (`nil` = not motion; legacy motion returns exactly one).
- **D6 Heading = chord direction, mirrored** (decided 2026-10-17). Each fed sample sets the heading to the chord just travelled, so a quarter arc ends at −89.55°, not −90°. Zigzag reads it per update. Pinned by name so nobody "fixes" it.
- **D7 Angles.** Headings are compass angles (ADR-007: 0° = up, x via sin); Arc's angle around its centre is a math angle (`atan2(y−cy, x−cx)`), exactly as in Catroid. The ADR says so explicitly.
- **D8 File format — keep v1, amend ADR-037** (decided 2026-10-17). v1 may grow additively until the first build is distributed to anyone else; from then on new vocabulary bumps the version, and a document stamps the *lowest* version that can represent it (exhaustive `requiredFormatVersion` walk). Sample JSONs stay byte-identical. The amendment pins all three operations of the post-freeze rule (Codex brief review, finding 3), since ADR-037's `admit` today accepts only `== currentFormatVersion`: **encode** derives the stamp from content, never from the stored `Program.formatVersion`; **decode** admits every supported version ≤ current; **decode refuses** a document whose content needs a newer version than its stamp (`formatVersion < requiredFormatVersion(program)`). None of it is built in this feature — v1 stays the only version — but the rule is written now so the freeze cannot happen without it.
- **D9 Locked formulas.** `ReadOnlyFormulaReason.function` and `.sensor`, each with a localized reason, rendered through `FormulaText`.
- **D10 Model additions.** `ArcDirection { left, right }`; `BrickDefaults` `arcDirection = .left`, `arcRadius = 10`, `arcDegrees = 360`, `goThrough* = 0` — Catroid has no `BrickValues` entry, the provenance is `CategoryBricksFactory.kt:1091-1092`. Slots `.radius`, `.direction`, `.throughX`, `.throughY` (GoThrough's destination reuses `.x`/`.y`); `ParameterValue.arcDirection`, `ParameterEditorKind.arcDirection`.

**New ADRs**: **ADR-046** (formula functions and sensors: D1–D4), **ADR-047** (Arc and GoThrough execution: D5–D7, cross-referencing ADR-018). **Amendments**: ADR-037 (D8), ADR-040 (lock reasons, direction control).

## Acceptance criteria

- [x] Every `Brick` and `Formula` case round-trips through `ProgramDocument` and is reflexively `==` — a property over a case census that fails to compile when a case is added.
- [x] Every function matches a characterization table derived from Catroid: within 1e-9 absolute for near-unity results, within a few ulps *relative* for large-magnitude ones (ADR-017: a fixed absolute tolerance is only valid near unity — `tan(90)` ≈ 1.633e16 has an ulp of 2), and exact where the value is exact or on an ADR-019 threshold (`log(1000) == 3`, `round(-2.5) == -2`, `round(0.49999999999999994) == 0`). Residuals Catroid produces are pinned, not snapped (`sin(180)` ≈ 1.2246467991473532e-16, not 0). Every divergence (D2 a–d) has a named test.
- [x] No formula built from these functions traps or hangs for any finite inputs — a property over generated trees, including `mod(-MAX, 1)`.
- [x] Every executed Arc or GoThrough costs exactly one tick, feeds the pattern once per sample whose position changed (at most 100), emits one `.needleMoved` per feed followed by that feed's stitches, and emits exactly one unchanged update when no sample changed position.
- [x] `arc(left, r, −d)` is event-for-event identical to `arc(right, r, d)`; `arc(_, −r, d)` to `arc(_, r, d)`.
- [x] Every Arc sample lies on its circle; every GoThrough ends exactly on its destination and passes through its through-point at sample 50 (1e-9).
- [x] No Arc or GoThrough leaves the needle non-finite; a bad formula or a non-finite sample leaves needle and heading unchanged and emits one update.
- [x] Sensors read the acting object's own needle at the moment the brick evaluates; `motionDirection` lies in (−180, 180].
- [x] Every palette kind, row sentence and new formula node has String Catalog entries; Arc's direction is editable as one undoable `replaceBrick`; function and sensor formulas are shown locked with a reason.
- [ ] The new sample runs and exports, and its `.dst` opens correctly in Ink/Stitch (manual check). *Runs and exports (`ArcFlowerTests`, `SampleDSTTests`); the Ink/Stitch check is pending.*
