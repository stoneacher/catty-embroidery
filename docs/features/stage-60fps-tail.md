# Stage 60 fps tail

**Status**: Planned — 2026-10-29 | **Epic**: E4 | **Branch**: `feature/stage-60fps-tail`

**Goal**: settle where M3's last unmet exit criterion goes. At 50 001 stitches (`makeUS309SyntheticProgram`) the mid-gesture median and p95 sit at one refresh period, but the worst frame is 38–50 ms against the bar's 33.3 ms (ADR-043 "Where it stands"). Coarsening is exhausted and the commit is excluded (the tail shows up in a single gesture that is never released). This feature runs ladder rung 3's discriminating experiment: does the tail move with the **pixels drawn**, with the **dots** or the **thread**, or with none of them? It builds the instrument that makes the experiment repeatable and agent-runnable, records the verdict, and then either ships a fix that meets the bar on device or names the next rung with evidence. **The outcome is unknown at planning, so "done" is defined independently of it (D8).**

**In scope**
- A DEBUG overlap-density fixture: the synthetic's stitch count and structure, packed into a small area (D1–D2). A zoomed-out condition on the existing fixture (D3). Two DEBUG renderer controls that draw only the thread or only the dots while live (D1).
- A DEBUG scripted-gesture driver, launched by argument, that drives the real coordinator (D4), and a console report (D5).
- Attribution: DEBUG signposts, an Animation Hitches trace and a Time Profiler trace per condition (D9).
- The device session, a decision rule fixed before measuring (D6), and the verdict as an ADR-043 amendment.
- The conditional fix half (slice 7), capped at two candidates, or no fix when the verdict is inconclusive (D8).
- **US-322** (raster never composited at a fractional viewport): measured in PR 1 by the report's canvas, viewport and raster fields, and fixed in PR 2 as a slice that does not depend on the verdict (D10; accepted 2026-10-29).

**Out of scope**
- Rung 5 (`MetalStitchRenderer`): a milestone of its own (ADR-029). If the verdict points there, it is named and gets a backlog item, not built here.
- **The A15-class capture**: blocked until a fix exists. If slice 7 ships one, the capture is *unblocked* and stays a milestone item that needs an A15 device in hand; not taken here unless one is paired (D11).
- The animating path's GPU-side hitches (ADR-029's 2026-09-18 amendment): recorded, not this feature's bar. They are re-captured only as a no-regression check after US-322.
- Viewport-culled planning (ADR-044's "deliberately not built" list) and momentum.

## Decisions (D1–D11, accepted by Sebastian 2026-10-29 as planned by `swift-architect`; D1, D2, D4, D6–D9 revised the same day after the Codex brief review, all 7 findings taken)

- **D1 Conditions, and what each can and cannot say.** No single fixture can hold the geometry and vary only the area. The running stitch rounds every stitch to whole stage points (`RunningStitchPattern.update`, `javaRound`), so a hatch packed into a tenth of the height puts about ten rows on the same `y`. Exact geometric control is therefore not claimed for any fixture. The experiment uses five conditions, all panned at fit except C:
  - **A0: the shipping fixture** (`us309Synthetic`), the baseline.
  - **B: an overlap-density fixture at fit** (`us316Compact`). Held: stitch count, colour runs and their lengths, stroke widths, transform (the fit is the same for any design inside the hoop, `StageGeometry.fitTarget`). Pinned but not exactly equal: segment and dot counts, corners, traversals (slice 1 records the actual values beside A0's). **Varied**: the covered area (the union, by ≥ 10×). **Also varied and uncontrolled**: coincident rows (many rows round onto one `y`), the row-transition segments (the anchor stays where a row ended, so the next row starts diagonally), dot overlap and antialiased edge topology.
  - **C: A0 zoomed out** (D3). Same plan, same `Path` element count, both the covered area and each primitive's area shrunk.
  - **D: A0 with the live dots suppressed** (DEBUG renderer control). The thread is drawn, the dot path is neither built nor filled.
  - **E: A0 with the live thread suppressed** (DEBUG renderer control). The dots are drawn, the stroke paths are neither built nor stroked.
  - **What the conditions can say** (with D6's classes): **pixel-sensitive** if B or C is clean while A0 tails; **not moved by pixel controls** if A0, B and C all tail; **dots** if D is clean and E tails; **thread** if E is clean and D tails; **both or neither** otherwise. B alone never names "covered area" as the cause, because its uncontrolled differences move with it. A causal claim needs at least two conditions agreeing (for example C clean *and* D clean says "dot fill"). Any other pattern is recorded as it is and goes to D8's inconclusive branch.
- **D2 The overlap-density fixture: `makeUS316CompactProgram`, only `rowSpacing` changes, to 0.1.** The integer stitch length rules out shrinking by length (ADR-017 truncates through `interpretInteger`, and 1 would only halve the size while changing segment lengths). A narrower row changes the stitches per row and with them the count and the corners. Spacing is the only free knob. **0.1 is preselected**: the original's 250 rows at 1.5 span 375 points, at 0.1 they span 25 (15×); 0.25 would give only 6× and fail the ≥ 10× criterion. It does **not** inherit the original's half-stitch argument: with the anchor left where a row ended, the next row's distance is about √(400² + spacing²), close to the floor boundary at 400 lengths. So slice 1 pins the exact count (50 001) **and** the measured minimum distance, in ulps, from any `floor(distance / length)` boundary over the whole interpreted fixture (the ADR-019 screening helper `SampleThresholdTests` uses), and fails if it drops below 10⁶ ulps. If 0.1 fails that, the next candidate is 0.125, then 0.15; nothing above 0.15. It lives in `Samples` under `#if DEBUG`, as `SampleID.us316Compact` with `resourceName` "US316Compact". It is not in `SampleLibrary.all` or `SampleID.shipping`, it is listed after `us309Synthetic`, and it shows the frame-time capsule. A test-only synthetic was rejected: only a sample can be captured on device.
- **D3 The zoom condition: zoom below fit is allowed and changes what "area" means.** `StageZoomBounds(fitting:)` allows zooming down to `min(fit, 0.05)`. Width scales until the 0.75 pt floor (scale ≈ 0.238). Below the floor, dots stop shrinking and segments shrink only in length. C is taken at the scale where the covered view area is ≤ 1/10 of A0's. The driver reaches it with a real pinch and a release (one commit), waits 2 s for the bake, then pans only. The console line prints the scale and the widths, so the real reduction is recorded rather than assumed.
- **D4 The driver is a coordinator-path surrogate, not a finger.** It drives the real coordinator, not the value types beside it, but it skips UIKit's touch delivery, so it is never described as reproducing a finger. DEBUG only, active only with `-US316Capture …` (the parser is pure and takes `[String]`). When the argument is present, `StageManipulationCatcher.makeUIView` registers its `Coordinator` with the driver. The driver calls the coordinator's own `panned(_:)`/`pinched(_:)` with scripted `UIPanGestureRecognizer`/`UIPinchGestureRecognizer` subclasses that override `state`, `translation(in:)` and `location(in:)`. That is the pattern `StageManipulationDoubles` already measured to work; assignment is silently swallowed. A `CADisplayLink` steps it, and the position is a pure function of `targetTimestamp`, so a stall makes the next step jump the way a moving finger does. Without the argument nothing registers, so the parallel suites never touch it.
  - **Reproduced exactly, from the action methods down**: the suppression gate, `beginManipulating` (ADR-044's frozen fit), the `StageManipulation` channels, the binding writes that invalidate SwiftUI, `gesture(in:)` → `rendering` → `isLive` and `canUseRaster == false`, `StitchDrawPlan.forFrame`'s coarse plan, the `Canvas`, `StageDrawCounter`, and at the end `settleIfFinished` → one commit → `onCommitted` → the re-bake.
  - **Not reproduced**:
    - UIKit's touch delivery: hit-testing, `UITouch`/`UIEvent`, target dispatch, the recognisers' state machines and simultaneous arbitration, `StageTouchTrackingView`'s `activeTouchCount` (which gates `settleIfFinished`'s commit; under the driver it stays 0, so the last channel's `.ended` commits where a finger's commit usually fires from the count reaching 0), and the stage's `simultaneousGesture(tapOutOfName)`. All of this is main-thread work, and the tail is a main-thread stall (D9), so the driver can *under*-report input cost.
    - In the other direction, the driver adds its own display link on the main thread, which a finger does not, so it can also *add* a cost.
    - Cadence: one update per refresh (drawn/n ≈ 1.0), against 0.6–0.97 by hand, so the driver draws *at least* as many frames as a finger.
    - Human jitter.
    - Any system policy keyed on real touches, such as performance-controller boosting (undocumented; treated as unknown).
  - **Hence the calibration** (D7): the driver's numbers count only once paired hand runs agree with it within limits fixed in advance.
- **D5 The console report is the capsule's line, plus fields.** The caption formatting moves from `FrameTimeReadout` into a pure `FrameCaptureReport`, so the capsule and the console print the *same* `n= drawn= commits= Hz med p95 p99 max@ · s · verdict` text. The console line adds the tag `US316`, the condition, every drawn interval > 33.3 ms with its offset, `ProcessInfo.thermalState` at the start and end (captures at `.serious` or worse are discarded), and the scale and widths. For US-322 it also prints the viewport, the `Canvas` size and whether the raster composited on the last settled frame, recorded by `StageDrawCounter` in DEBUG.
  - The driver owns its own `FrameTimeRecorder`, so the capsule stays untouched and on screen for parity.
  - `stdout` is flushed per line (it is block-buffered when not a TTY).
  - The idle timer is disabled while capturing, and the app calls `exit(0)` after its one run (one launch is one run, D6), so `devicectl device process launch --console` and `xctrace --launch` both return unattended.
- **D6 The decision rule, fixed before the first capture** (ADR-030's practice). It is a **predeclared classification, not a significance test**: five runs on one device cannot carry a statistical claim, and the per-run values are always reported beside the class.
  - **A run**: one launch, a full pre-roll run, 2 s of settling, then a 12 s pan-only gesture that is never released, inside a signposted window. **Every run is recorded under `xctrace --launch` with the Animation Hitches template**, so no trace is chosen after seeing the numbers. Per run the record is: from the capsule, the drawn-frame p99, the worst drawn interval and every drawn interval > 33.3 ms; from the trace, the number of hitches and of hitches > 33.3 ms inside the window, and the worst hitch duration.
  - **A run is over** if either instrument shows a frame or hitch > 33.3 ms inside the window. (ADR-043: the capsule cannot see GPU or compositor misses, so it alone never makes a run clean.)
  - **Five runs per condition**, launches interleaved A0, B, C, D, E, A0, … so thermal drift spreads across conditions. Runs at `ProcessInfo.thermalState` `.serious` or worse are discarded and re-taken.
  - **Classes**: a condition **tails** if ≥ 3 of 5 runs are over; it is **clean** if 0 of 5 are. **1 or 2 of 5** is unsettled: 5 more runs, once, then **tails** at ≥ 6 of 10, **clean** at ≤ 1 of 10, and **inconclusive** otherwise.
  - **The mixed pinch-and-pan script is a supplementary condition, always captured**, 5 runs on A0 only. It does not replace any pan-only result. If pan-only A0 is clean but mixed A0 tails, the scale change is implicated and the result is recorded as such (no further matrix in this feature).
  - A0 pan-only must tail under the driver for D1's table to apply. If it does not, the result is "A0 does not tail under the surrogate" and D7's calibration decides what happens next.
- **D7 Which captures need the human.**
  - Once per machine: Xcode opened and its device-access prompt approved, which `xctrace` needs (the us-309 handoff, item 1), and auto-lock disabled.
  - **Calibration**: 3 hand runs and 3 driver runs of A0, alternating, all recorded as in D6. The driver is accepted as a surrogate if **both** of these hold: the two sets fall in the same class (over in ≥ 2 of 3, or in ≤ 1 of 3), **and** the driver's total count of hitches > 33.3 ms over its 3 runs is at least half the hand's. The drawn-frame cadence and the Time Profiler's top frames are recorded for both, but they are not part of the test. **If the calibration fails, the whole D6 matrix (A0, B, C, D, E and the mixed A0) is taken by hand**, with no reduced fallback, so D1's table can still be read.
  - **Acceptance of a fix**: one hand run of at least 10 s, recorded under `xctrace --launch` with the Animation Hitches template, the human gesturing (D8).
  - **Judgement**: any fix that changes the live image is looked at by eye on the device.
  - Everything else (the matrix after a passed calibration, every Hitches and Time Profiler trace, the US-322 re-capture) is agent-run with `devicectl --console` and `xctrace --launch`.
- **D8 Done, whatever the result.** (1) Instrument, fixture and controls built and green. (2) The calibration and the D6 matrix captured. (3) The result recorded as an **ADR-043 amendment** with the per-run values, in `docs/us-316-device-handoff.md`, and in the journal. Then **one** of three endings:
  - **Fixed**: a fix meets the bar on device. The bar is quoted verbatim and never reworded (ADR-032 invariant 1): *"Over a capture of at least 10 s: p99 ≤ 16.67 ms and no frame > 33.3 ms, over drawn frames only."* Evidence: a hand run of at least 10 s whose capsule gives the drawn-frame p99 and no drawn frame > 33.3 ms, **and** the Animation Hitches trace of **that same run** shows no hitch > 33.3 ms inside its window (the capsule alone cannot carry the second clause, ADR-043). Driver runs support the fix but never claim the bar. "Where it stands" is amended to met.
  - **Next rung named**: D1's table points at a cause (two conditions agreeing, D1), the fix candidates for that cause were tried (at most two) and missed, or the cause belongs to rung 4 or 5. The amendment names the rung and the conditions that point to it. The criterion stays recorded **unmet**.
  - **Inconclusive**: no causal claim is supported (an inconclusive class, a failed calibration whose hand matrix is also unreadable, contradictory conditions, or a confound in B that decides the reading). The amendment records that there is no verdict, names the validity failure, and scopes **exactly one** next experiment. The criterion stays recorded **unmet**, and no fix is attempted.
  - A fix candidate is tried only after a causal claim: the condition that removes the cause is clean while A0 tails. A candidate that misses is recorded and does not open a third.
- **D9 Attribution: what each instrument can and cannot say.** A display-link interval widens only for main-thread stalls (journal, 2026-09-18), so the capsule's 38 ms is CPU on the main thread. A fill-rate cost may also sit on the GPU, where only the Hitches trace sees it.
  - DEBUG `OSSignposter` intervals (Points of Interest) around `forFrame`, `segmentPath`, `dotPath` and the stroke and fill calls, plus one interval for the whole capture window.
  - One Time Profiler trace of A0 and of each clean condition. **Its conclusions are limited to CPU work**: building the `Path`s and submitting them. Neither it nor the signposts can measure scan conversion, which happens later, partly on the GPU.
  - **The dot-versus-thread split is settled by conditions D and E** with their Hitches traces, not by CPU sampling. `addRect` for `addEllipse` is never chosen only because `dotPath` looks cheap or expensive in Time Profiler.
  - ADR-043's per-frame display-list copy is excluded: no append happens while settled.
- **D10 US-322 comes in.** The backlog pulls items into features that touch the same code, and this one does (`CanvasStitchRenderer`, `compositingRaster`). It cannot change a mid-gesture frame, since `canUseRaster` is false while live. But it governs the frames before and after the gesture, and it confounds every settled or animating device number. PR 1 measures it for free (D5); PR 2 fixes it first, so the fix captures run on a correct raster gate.
- **D11 Risk and the A15.** The fixture (engine package) and every renderer change are **risky**. The driver, the report and the scenario are DEBUG-only app code with no shipping path, so they are not risky, but the reviewer checks D4's fidelity claim against the coordinator. `release-build.yml` proves that nothing leaks into a build without `DEBUG`.

## Acceptance criteria

- [ ] `us316Compact` has exactly 50 001 stitches, 5 colour runs of the original's lengths, a covered height ≤ 1/10 of the original's, and a floor-boundary margin ≥ 10⁶ ulps; its segment, dot, corner and traversal counts are pinned as literals beside A0's, and its uncontrolled differences (D1) are listed in its doc comment. Both fixtures are DEBUG-only, outside the library, and listed last.
- [ ] The live-dot and live-thread controls change only what they suppress, only while live, and only with their launch argument present (DEBUG).
- [ ] One launch argument runs a capture end to end, with no touch on the device. It prints a line whose statistics are byte-identical to the capsule's for the same recorder state, then exits.
- [ ] On the coordinator path, scripted recognisers give the same binding writes as the existing stub-driven tests: live throughout, `canUseRaster == false`, and exactly one commit, at the end. (Touch-delivery fidelity is not a test claim; it is the calibration's question, D7.)
- [ ] The calibration and the D6 matrix were captured on the iPhone 17 Pro with every run traced. The result (a verdict, or "inconclusive" with its validity failure and one next experiment) is recorded as an ADR-043 amendment with the per-run values.
- [ ] US-322: a fractional viewport no longer refuses the raster (red first), and the animating 50k capture plus its Hitches trace are re-taken with no regression.
- [ ] One of D8's three endings, with its evidence. For "fixed", ADR-043's bar holds as written, *"Over a capture of at least 10 s: p99 ≤ 16.67 ms and no frame > 33.3 ms, over drawn frames only"*, on one hand run whose capsule supplies the drawn-frame p99 and whose Animation Hitches trace supplies the no-frame-over-33.3-ms clause. The bar's wording is unchanged in every document.

## Slices and test-first outline

Each slice goes red → green and is mutation-checked. Before any test, the brief gets **one Codex round**, aimed at D1's reasoning, D4's fidelity claim and D6's rule: they are new and not pinned by any ADR (ADR-041).

**PR 1 — the instrument and the verdict** (~650 lines of non-test code; the shipping render path untouched)

1. **Overlap-density fixture** (risky: yes, engine) — red, in `StagePreviewTests`/`SamplesTests`: stitch count `== us309SyntheticStitchCount`; 5 runs, with per-run lengths equal to the original's; the floor-boundary margin over every needle update ≥ 10⁶ ulps (D2); the live plan's segment and dot counts (via `forFrame` at a live transform), corners and traversals pinned as literals for **both** fixtures; a bounding-box literal with height ≤ original/10; not in `SampleLibrary.all` or `shipping`; `resourceName` valid for DST `LA`. App: `SyntheticHarnessTests` asserts both fixtures are last, in order, and that the capsule shows for both. Mutations: spacing on a floor boundary (count drifts), spacing ≥ stitch length (+250 stitches), 4 bands, row width ±1, spacing 0.25 (height criterion), added to `SampleLibrary.all`.
2. **Scenario, script and report** (risky: no) — red: the parser (absent → nil; each fixture, zoom, gesture and hold; unknown → nil; hold below 10 s rejected); `GestureScript` (starts at a zero translation like the recogniser; continuous, with a bounded per-frame step at 60 Hz; a pan-only script never changes scale; it keeps the design on screen; it is time-based, so a skipped tick jumps); `FrameCaptureReport` (the capsule caption is unchanged, which `FrameTimeReadout` is switched to; the console line carries the over-bar list, the thermal state and the scale, canvas, viewport and raster fields). Mutations: the over-bar list taken from all frames rather than drawn ones, a frame-count-based script, scale drift in the pan script, a 5 s minimum hold.
3. **Driver wiring** (risky: no; reviewer checks D4) — red, beside `StageManipulationWiringTests`: the scripted pan and pinch through the real `Coordinator` give live renders, no commit mid-script and exactly one at the end; the zoom pre-step commits once and lands at the requested scale; the sequence (select → play → finished → settle → [zoom] → record → gesture → stop → report → exit) is a pure state machine; nothing registers without the argument. Simulator dry run with `simctl launch --console`. Mutations: committing every step, skipping `beginManipulating`, registering unconditionally, never ending the gesture.
4. **Signposts, the draw record and the live controls** (risky: yes, renderer file, DEBUG-only) — red: the draw record reports the `Canvas`'s `size` and not the viewport, and whether the raster composited; with the dot control, a live frame draws the thread and no dot, and a settled frame draws both; with the thread control, the reverse; without either argument both are drawn; `CanvasStitchStrokeTests` stays green. Mutations: `size` recorded from the viewport, composited recorded from `canUseRaster` alone, a control applied to settled frames too, a control applied without its argument.
5. **Device session: the measurement** (no code) — the build is the us-309 handoff's Release-with-`DEBUG` command; install and `launch --console` on device 00008150-001525401181401C. Order: calibration (D7), then the D6 matrix (every run traced), then the Time Profiler traces (D9). Outputs: `docs/us-316-device-handoff.md` (protocol and per-run values), the ADR-043 amendment with the result (a verdict or "inconclusive", D8), and a journal entry. **PR 1 is ready for review here**, with its Codex loop.

**PR 2 — US-322 and the fix** (branch `feature/stage-60fps-fix`; size depends on the verdict)

6. **US-322** (risky: yes) — red: `compositingRaster` with a 370 × 256.833 viewport against a 370 × 257.0 `size`. The keying choice is taken from the backlog's three options at the red phase, and recorded as an ADR-043 amendment because it touches "never stretched". Re-capture the 50k animating run and its Hitches trace (agent-run). Mutations: an exact-equality comparison restored, a tolerance ≥ 1 device pixel.
7. **The fix, conditional on the verdict** (risky: yes; skipped when the result is inconclusive; at most two candidates; each one captured with the driver, 5×, before the next):
   - *Pixel-sensitive and dot-dominated (D clean, plus B or C clean)* → (i) `addRect` for `addEllipse` while live (ADR-030's renderer-only alternative). *Pixel-sensitive and thread-dominated*: (ii) only. Red: `dotPath` in live mode emits rectangles of the same centres and extent. (ii) The live frame drawn at a reduced backing scale. Both change the live image, so each needs an ADR-043 "accepted fidelity costs" entry and the human's look (D7).
   - *Not moved by pixel controls, and the Time Profiler names the CPU `Path` build* → rung 4: `Path` reuse keyed on plan and stride, built in stage space and drawn under a transform, with the width divided by the scale and the 0.75 pt floor kept. **First** harden the engine polyline against non-finite and unconvertible vertices. Red: it drops exactly the vertices the fine plan's `isDrawable` skips. Then a cache key test: a pan re-uses the cached path, and a stride, reset or run change invalidates it.
   - *Not moved by pixel controls, and not the CPU `Path` build either* (layout, diffing, input) → no fix. The amendment names the cost and the next rung.
   - The winner gets the hand run and its Hitches trace (D8 "fixed"). Mutations per candidate: the live gate inverted (rectangles drawn when settled), the cache key missing the stride, a width not divided by the scale.
8. **Close** — ADR-043 "Where it stands" amended (met, or still unmet with the next rung); US-316 removed from the backlog, or re-scoped there to the named rung; the A15 status stated (D11); `swift-documenter`; journal.
