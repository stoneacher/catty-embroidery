# Language-test runner

**Status**: In progress — PR 1 (slices 1–4) in review, 2026-11-03; planned 2026-11-03 | **Epic**: E3 (program model & interpreter) | **Branch**: `feature/language-test-runner` (PR 1, #86; PR 2 gets its own branch)

**Goal**: the engine runs the Catrobat Language Tests, the implementation-independent `.catrobat` programs Catroid ships in `catroid/src/androidTest/assets/catrobatTests/`, headlessly inside `swift test`, and reports how many of the 215 pass. Every test is pinned to an expected class: pass, expected failure (with its ADR) or unsupported (with the features it needs). A test that changes class turns the suite red until the table is updated on purpose. A partial `code.xml` → `Program` importer, the S* `.catrobat` import's first half, comes with it.

**In scope**
- A `code.xml` importer for the supported bricks, formulas and the two Start-script shapes, in a new `CatrobatImport` target.
- `AssertEquals`, `FinishStage`, `ExitStage` and `WaitTillIdle` as **harness steps**: interpreted, but never `Brick` cases. So none of them reaches `BrickKind`, the palette or `ProgramDocument`.
- An empty script (`EmptyScript`) is skipped on import.
- All 215 `code.xml` files committed as fixtures, with a provenance manifest and a reproducible extraction script.
- A parameterised runner with pinned per-test classes and pinned summary counts.

**Out of scope** (each deliberate)
- **Strings as values** (decided 2026-11-03). The Variables brief deferred them to this feature (its D1); they are deferred again. Our values stay `Double` (ADR-048), and a string that would be *compared or stored* is refused on import (D4). That costs two runnable tests: `bricks/control/testForLoopWithChangeVariableBrick` and `data/testSetAddVar`.
- Everything ADR-001 leaves out: lists, broadcasts, clones, looks, physics, touch and colour sensors, user-defined bricks. That is about 177 of the 215.
- `rand` (deferred by ADR-046; it would add `formula/testRandomFunction`).
- Importing a `.catrobat` in the app, and unzipping. The fixtures are extracted `code.xml` files, so the engine needs no zip.
- Moving the suite into Catrobat's planned language-specification repository, writing new language tests, and triaging Catroid's open `catrobatTests` PRs (ROADMAP, 2026-10-19 update).
- `WaitTillIdle` in the palette. It is a real Catroid control brick, but a harness step here; making it user-facing needs a `Brick` case and a format addition, and with one object in the app it is a no-op anyway.

**Brief review**: done 2026-11-03. One Codex round, 8 findings (2 High, 5 Medium, 1 Low), all valid and all folded into this brief (journal). The two Highs: a string operand of `=`/`≠` is compared as a string in Catroid, so mapping it to NaN would make `"a" = "b"` true (D4); and an unrestricted `withKnownIssue` would keep an expected failure green when it starts failing for a different reason (D12).

- **D1 Version window: 0.99995 ≤ version ≤ 1.14** (decided 2026-11-03; it supersedes the 2026-10-19 decision to bring old tests up to 1.14 by re-saving them through Catroid). **None of the 215 tests is at 1.14** and only one is at 1.13. The 34 runnable ones span 12 versions from 0.99995 to 1.12. For our bricks the format is the same across that window:
  - The 1.13 and 1.14 bumps changed no format code. 1.14 (`a949f79b5`) added XStream aliases for plot and laser bricks; 1.13 (`18645e92e`) touched only `Constants.java`.
  - Catroid's load-time upgrades (`ProjectManager.java:143-175`) don't reach our set, except `updateDirectionProperty` for versions ≤ 1.03 (`OBJECT_ROTATION` → `MOTION_DIRECTION`, `formulaeditor/Formula.java:114-119`). The importer **refuses `OBJECT_ROTATION`** as an unsupported sensor; no runnable test uses it.
  - The parent/child tag pairs of every runnable test match the 1.11–1.13 tests'. The two outliers, both read by Catroid 1.14's XStream, are accepted: a variable written as text (`<userVariable>Counter</userVariable>`) and a fully qualified tag (`<org.catrobat.catroid.content.bricks.AssertEqualsBrick …>`).

  Re-saving would have needed an Android round trip and churned brick IDs and `reference=` paths for no format gain. A version outside the window is refused (`version`). One target still holds: the importer parses the 1.14 shape, and nothing reaches back past it. The supervisor is informed, not asked.

- **D2 AssertEquals equality.** Catroid evaluates both sides with `interpretObject` (`content/actions/AssertEqualsAction.kt:49-50`) and passes iff `actual == expected || actual.toDouble() == expected.toDouble()` on their strings (`content/actions/AssertAction.kt:45-50`). NUMBER and STRING nodes return their raw text (`formulaeditor/FormulaElement.java:408-410`), so a literal `1` and a computed `1.0` compare numerically. Over our `Double` values that reduces to ADR-048's one equality, the existing `Double.isSameValue(as:)` (`ProgramModel/DoubleEquality.swift:5`, made `package`): NaN = NaN (Catroid's `"NaN" == "NaN"`) and −0 = +0 (`toDouble ==`). Evaluation must not throw: a new `package func interpretValue(scope:)` returns the raw `Double`, NaN included, where `interpretDouble` throws on NaN (`Formula+Evaluation.swift:9-15`). *Refined at slice 3's review:* NaN = NaN holds only through the string test, because Kotlin's `Double ==` is IEEE and a computed NaN prints as exactly `"NaN"`. So an assert literal spelled `-NaN`, `+NaN` or ` NaN `, which parses to NaN, matches nothing in Catroid, and the importer refuses it (`stringValue(.assertOperand)`). Only the exact text `NaN` imports as NaN there.

- **D3 Harness steps stay out of `Brick`.** The importer produces an `ImportedProgram` that mirrors `Program`, with scripts as `[ImportedStep]` = `.brick(Brick) | .assertEquals(actual:expected:) | .finishStage | .exitStage | .waitTillIdle` (first planned as `assertEquals(actual:expected:position:)`). *Restated at slice 4:* the case carries no position; the runner reports one from the object, script and step indices, which are the imported program's (skipped scripts are absent), together with the object's name. `ImportedProgram.program()` refuses harness steps, which serves the later app import. The interpreter gains a `package init(harness:)` over `[ScriptStep]` and an `Instruction.harness` case. `compile` and `validate()` work on the brick projection; harness steps are leaves. The outcome is a `package var harnessResult`, not new `InterpreterEvent` cases, so the exhaustive switches in StagePreview and the app stay untouched. *As built at slice 5:* `ScriptStep` = `.brick(Brick) | .harness(HarnessStep)`, the outcome comes from `runHarness(budget:) -> HarnessRun` (outcome, ticks, events), and `InterpreterEvent` is untouched as planned. ADR-037 holds by construction.

- **D4 String literals are mapped by context, mirroring Catroid, or refused** (refusal decided 2026-11-03). A literal matching Java's decimal grammar without an `fFdD` suffix, or exactly `NaN`, becomes `.number(Double(s))`. Otherwise:

  | Where the literal sits | Catroid | Import as |
  |---|---|---|
  | Brick root (a number slot) | `Double.valueOf`; on failure `InterpretationException`, which acts as NaN (`formulaeditor/Formula.java:139-161`) | `.number(.nan)` |
  | Operand of any other operator | NaN on failure (`formulaeditor/common/FormulaElementOperations.kt:79-88`) | `.number(.nan)` |
  | Function argument | `tryParseDouble` rejects `fFdD` (so `"Infinity"` too), and a null argument makes the function return 0.0 (`formulaeditor/common/Conversions.kt:35-44`; `UnaryFunction.kt`, `BinaryFunction.kt`: `?: return 0.0`) | the whole call folds to `.number(0)` (`ARCSIN('abc')` expects `FALSE()`) |
  | Operand of `=` or `≠` | numeric comparison if both sides parse, otherwise the two strings are compared (`formulaeditor/common/FormulaElementOperations.kt:67-75`); the other comparisons and arithmetic go through `tryInterpretDoubleValue` → NaN (`FormulaElement.java:813-818`) | **refused** (`stringValue(.equality)`); NaN would make `"a" = "b"` true (`bricks/control/testIfThenBrick`, `code.xml:491-508`, out of scope for user bricks anyway) (Codex brief review, finding 1) |
  | AssertEquals operand, SetVariable value | compared or stored as a real string | **refused** (`stringValue(context)`); mapping to NaN would let `"abc" = "xyz"` pass. *Corrected at slice 3:* ChangeVariable is **not** a string context. It parses with `toDoubleOrNull` and skips the change on failure (`content/actions/ChangeVariableAction.kt:41-45`), which is our NaN → 0 substitution, so it is a number slot. SetVariable parses with `tryParseDouble`, so `fFdD` is refused there too (`SetVariableAction.kt:49-64`) |

  A non-finite NUMBER literal is refused, since Catroid keeps the raw string `"1e400"` rather than normalising it (`FormulaElementOperations.kt:91-104`).

  *Added at slice 3's review (Codex, findings 1–2):* **what a SetVariable stores** is a separate question from its value. A root STRING is stored as a string even when it is `"2"` (`isFirstLevelStringTree`, `SetVariableAction.kt:53-59`); a logical root (comparisons, `and`/`or`/`not`, `TRUE`/`FALSE`) is stored as a `Boolean` (`:49-51`, `FormulaElement.isBoolean`); a USER_VARIABLE root copies a Boolean. Every read normalises both back, so the imported value is right. But ChangeVariable skips a non-`Double` (`ChangeVariableAction.kt:41`), and ForVariableFromTo exits when its control variable is one (`ForVariableFromToAction.java:60`). A per-formula refusal would cost 9 of the runnable tests, which set variables from comparisons, so `FormulaImport.storage(ofVariableValue:)` reports the kind, and **slice 4 refuses a variable that some SetVariable stores as a Boolean or a string (directly or through a copy) and that is also a ChangeVariable target or a ForVariableFromTo control variable** (`variableStorage(name)`).

  *Refined at slice 3:* "Java's decimal grammar" means `Double.valueOf`'s exactly: surrounding characters ≤ U+0020 trimmed, an optional sign, `NaN`/`Infinity`, decimals and hexadecimals (with a mandatory `p` exponent), and an optional `fFdD` suffix. Brick roots, operator operands, equality operands and assert operands use it. Function arguments and SetVariable values use `tryParseDouble`, which first rejects any `f`, `F`, `d` or `D` anywhere, including `Infinity` and hex digits. A BRACKET passes its literal through unchanged, string included. A NUMBER or STRING with no `<value>` is Catroid's null, normalised to 0.0. Non-finite literals are refused in every position.

- **D5 Run outcome.** **The first result is latched; the run stops at the end of that tick.** `finishTestWithResult` ignores later results while the stage is finishing (`stage/StageActivity.java:490-498`), and a failing assert's `act` returns false, so its own thread goes no further. It does not abort `stage.act` (`stage/StageListener.java:584-593`), and `Activity.finish` is asynchronous, so the other threads complete the current pass. We mirror that: the round-robin tick finishes, later reports in it are ignored, and no further tick runs. How many more frames Catroid runs before teardown depends on Android, so stopping after the tick is our pinned policy (Codex brief review, finding 3). A failure reports the object, script and step index with expected and actual. `FinishStage` reports success (`content/actions/FinishStageAction.kt`). `ExitStage` is `createFinishStageAction(true)` (`content/bricks/ExitStageBrick.java:43`), so it ends the run without a result. A run that ends without a result, through ExitStage or by every thread finishing, fails as `endedWithoutResult`; Catroid waits out its timeout and fails. In all three tests that use it, ExitStage comes after FinishStage.
 *As built at slice 5 (PR 2 feature review):* one latch for every ending, not only results. Catroid's `finishStage()` (ExitStage) and `finishTestWithResult` both act only while the stage is not yet finishing (`stage/StageActivity.java:482-497`; this range supersedes the `:490-498` above), so the first ending of either kind wins, and a result after an ExitStage in the same tick is ignored.
- **D6 Tick cost and budget.** Each of AssertEquals, FinishStage and ExitStage is one action, because libgdx `SequenceAction` advances one child per frame. Like any action, it is deferred when the thread already acted this tick. The budget is **600 ticks**, a deterministic runner policy chosen after, but **not equivalent to**, Catroid's `TIMEOUT = 10_000` ms (`catroid/src/androidTest/java/org/catrobat/catroid/catrobattestrunner/CatrobatTestRunner.kt:68, 154`). That timeout is wall-clock, includes start-up and teardown, and Catroid subdivides each rendered frame into an adaptive number of `stage.act` calls (`stage/StageListener.java:584-600`), so no fixed tick count translates it (Codex brief review, finding 7). Boundary: a result reported in tick 600 counts; reaching tick 601 fails as `budgetExhausted`. No retries; Catroid uses 5 (`:50`). Every run records the ticks it used, and the runner requires every passing test to finish within half the budget, so a test that passes only near the limit shows up as a finding rather than a silent pass.

- **D7 Import mapping.**
  - **References:** XStream relative paths, where `name[n]` is 1-based and counts only siblings with the same tag (`../../brick[2]/userVariable`, `../../scenes/scene/objectList/object[2]/…`). In the runnable set, references only ever point at `userVariable`. An unresolved reference is refused.
  - **Declarations:** `programVariableList` maps to `Program.variables` and an object's `userVariables` to `Object.variables`. An entry is either an inline `userVariable` (`bricks/motion/testPlaceAtXY`, `code.xml:484-521`) or a reference to one elsewhere. **References are resolved over the complete XML tree before any commented-out brick or script is dropped**: `brick/testDisabledBrickInLoopRegression` declares `Counter` through a reference into a commented-out `ChangeVariableBrick` (`code.xml:48-57, 87-89`). Catroid deserialises the whole graph and skips such bricks only when building actions (`content/Script.java:126`, `content/bricks/RepeatBrick.java:180`) (Codex brief review, finding 5). Formulas read variables by name (the `USER_VARIABLE` value), which matches our lookup. Catroid binds identity; we bind names. They differ only when an object and the project declare the same name, so the importer **refuses that collision** (`variableShadowing`) rather than guess. No test in the corpus has one, so this costs nothing today. *Corrected at slice 4's review (Codex, finding 1):* "only" was wrong. A formula reads by name, and the first declaration wins (`UserDataWrapper.java:40`), so two same-named declarations in one list differ too. So does a brick whose variable no visible declaration holds: Catroid writes an object no read reaches, while ours would declare it on use. Both are refused (`variableShadowing`, `undeclaredVariable`); the corpus has neither. The storage rule is keyed by identity, so two objects' own `x` are apart.
  - **Structure:** `loopBricks` becomes body + `.loopEnd`. `IfLogicBeginBrick` becomes `ifElse` + `ifBranchBricks` + `.elseBranch` + `elseBranchBricks` + `.ifEnd`. `IfThenLogicBeginBrick` becomes `ifThen` + `ifBranchBricks` + `.ifEnd` (ADR-008). A `commentedOut` brick is skipped with its whole subtree (`content/Script.java:132`, `content/bricks/RepeatBrick.java:184`), and so is a commented-out script (`Script.java:101`). `NoteBrick` is dropped. A BRACKET node passes its child through; unary `MINUS` becomes `unaryMinus` and `LOGICAL_NOT` becomes `logicalNot`. A non-empty `additionalChildren` is refused. ADR-037's 128-node depth cap applies.
  - **Pose:** start at (0, 0) with heading **90** (`content/Look.java:88`); `testMoveXStepsFunction` depends on it.
  - **Scenes:** first scene only; more than one is refused. Catroid plays one scene, while `Interpreter.swift:42` runs every object it is given.
  - **Errors:** `throws(CatrobatImportError)`, which **collects every** blocker rather than stopping at the first: `brick(name)`, `script(name)`, `function(name)`, `sensor(name)`, `elementType`, `stringValue(context)`, `version`, `multipleScenes`, `variableShadowing`, `unresolvedReference`, `malformed`; slice 3 added `operatorName`, `nonFiniteLiteral`, `formulaShape` and `formulaTooDeep`, and slice 4 `element`, `brickShape`, `variableStorage`, `undeclaredVariable` and `harnessStep`. The runner builds its blocker histogram from these.

- **D8 WaitTillIdle** (decided 2026-11-03). Catroid's action is true iff every actor on the stage has no running script, or only the script running this action (`content/actions/WaitTillIdleAction.java:35-58`). Mirrored over our threads: one poll per tick, an action like `waitUntil` (ADR-049), satisfied when every *other* thread has finished, **as observed live at the waiter's position in the round-robin pass**. A worker visited before the waiter that finishes in this tick releases it in this tick; a worker visited after it releases it in the next (Codex brief review, finding 4). The corpus test `testWaitUntilAllOtherScriptsHaveStopped` puts the waiter first, so it pins the second ordering. An object with no scripts counts as idle (the test's Background exercises it). Mirrored too: two threads each in a WaitTillIdle never release each other, because neither counts the other as idle. A stage with no objects is never idle, which a thread-level "all others finished" check would get wrong vacuously, so it gets its own test. *Amended at slice 6:* that test cannot exist. A waiter always belongs to an object, so the stage it polls is never empty (slice 6 entry; Codex, slice 6, finding 3). *Corrected at slice 6's review (Codex, finding 1):* "observed live" is per object. Each Catroid actor's `ThreadScheduler.tick` acts all of its scripts and only then removes the finished ones (`common/ThreadScheduler.java:59-90`). So another object's script that has finished is gone at the poll, but one of the waiter's own object that finished *in this tick* is still listed, and a same-object worker ending just before the waiter releases it a tick later, not in that tick. *Added at the same review:* a WaitTillIdle inside a loop or If never releases, because Catroid checks only its script's top-level children (`WaitTillIdleAction.java:53-56`, not recursive). This is mirrored, since it is what Catroid does. *Corrected at PR 2's handover review (Codex, round 1):* scripts start per object too. Catroid queues every Start script before the first frame, but an object moves its queue into its action list only when its own `ThreadScheduler.tick` runs (`stage/StageListener.java:572-574`, `common/ThreadScheduler.java:59-70`). A poll in tick 1 therefore sees a later object's scripts as not yet started. So two waiters on different objects that both poll in tick 1 do release: the earlier one does. "Never release each other" holds once both have started.

- **D9 EmptyScript** (decided 2026-11-03). Skipped on import: it has no trigger, so the bricks it contains never execute. The corpus test `bricks/events/testEmptyEvent` cannot prove this on its own, because its EmptyScript, which holds an AssertEquals, is also `commentedOut` (`code.xml:38-59`), so the commented-script rule would pass it without any EmptyScript rule (Codex brief review, finding 6). A synthetic, non-commented EmptyScript holding a failing assert pins the rule.

- **D10 Package layout (ADR-042 amendment).** A new target, **`CatrobatImport`**, depends on `ProgramModel` only and is vended by no product, so no `pbxproj` change: eight targets, five products. XML is read with a Foundation `XMLParser` SAX pass into a small `Sendable` element tree (`XMLDocument` is macOS-only), with `#if canImport(FoundationXML)` so the target can build on Linux. Nothing builds on Linux yet (US-317), so this only keeps that door open. The test target `LanguageTestsTests` holds the fixtures and the runner, and depends on `CatrobatImport` and `Interpreter`; a small adapter there maps `ImportedStep` to `ScriptStep`. *As built in PR 1:* it depends on `CatrobatImport` and `ProgramModel`; `Interpreter` arrives with PR 2. The enum is `ProgramImport`, not `CatrobatImport`, which would shadow its module (feature review). **Linux:** the importer is written to build there; the provenance tests are not, since they hash with CryptoKit and record an issue per fixture without it.

- **D11 Fixtures** (decided 2026-11-03: all 215). Stored at `Tests/LanguageTestsTests/Resources/catrobatTests/<original path>/code.xml`, declared `.copy` so the tree survives. About 3 MB. `manifest.json` records, per test, the original zip path, the sha256 of the zip and of `code.xml`, and the language version, plus the Catroid commit and the asset directory's last commit. A `PROVENANCE.md` (AGPL-3.0, verbatim data) sits beside it. `scripts/extract-language-tests.sh <catroid-checkout>` regenerates the fixtures and manifest deterministically.

- **D12 The ratchet.** `@Test(arguments: LanguageTestCatalog.all)`, where each case carries a pinned class: `pass`, `expectedFailure(outcome, adr)` or `unsupported(Set<Blocker>)`. **An expected failure pins its exact outcome**, for example `.assertionFailed(position:expected:actual:)` at a named step. The test first requires a successful import and an outcome equal to the pinned one, outside any known-issue block, so a test that starts failing for another reason (an importer refusal, the budget, a different assert) goes red. Only then is that one assertion's issue recorded inside `withKnownIssue` with a matcher that accepts exactly it. Swift Testing's default matcher accepts every issue (`Testing.swiftinterface:823`), which would mask a changed cause (Codex brief review, finding 2). `withKnownIssue` with `isIntermittent: false` fails when no issue is recorded, so an expected failure that starts passing still turns red; that premise is executed first (ADR-032 invariant 4). An unsupported case asserts that its blockers are exactly the pinned set. A summary test pins the per-class counts and attaches `N/215` and the blocker histogram.

  *As built at slice 7 (PR 2 feature review):*
  - **Arguments and expectations:** `@Test(arguments: LanguageTestCatalog.entries)`, over `LanguageTestExpectation.all` with `.pass`, `.expectedFailure(HarnessAssertionFailure, owner:)` (object, script and step indices with expected and actual) and `.unsupported(Set<String>)` (exact `ImportBlocker.label`s).
  - **The summary:** `theSuitesResultIsPinned` pins the counts and prints `N/215`. It attaches nothing; the blocker histogram is `CorpusProgramTests.blockerKindsAcrossTheCorpus`.
  - **The table is generated** by `scripts/regenerate-language-test-expectations.sh` (an environment-gated test, `RegenerateExpectations`). Regenerating is idempotent, and a new expected failure needs its owner named by hand.

**New ADR**: **ADR-051**, Catrobat language tests: the version window, the import mapping and string contexts, harness steps, equality, outcome, ticks and budget, WaitTillIdle (D1–D9, D12). **Amendments**: ADR-042 (D10). **ROADMAP**: the 2026-10-19 re-save decision is superseded by D1, recorded as a dated update, not by editing it.

## Acceptance criteria

- [ ] All 215 fixtures are present, and their hashes match the manifest; the extraction script reproduces both from the pinned Catroid commit.
- [ ] Every one of the 215 imports or fails with typed blockers, and none crashes. Every successful import passes `validate()`.
- [ ] Every Catroid function, operator, sensor and element-type name that `Formula` supports maps to its case. A census over `UnaryFunction`/`BinaryFunction`/`FormulaConstant`/`Sensor.allCases` fails to compile, or fails, when one is missed.
- [ ] Each D4 string context is pinned by a named test, including a refused assert string, a refused equality operand and the function-call fold to 0.
- [ ] AssertEquals passes and fails exactly by `isSameValue` (NaN = NaN, −0 = +0, `1` vs `1.0`). After the first result the current tick finishes and no further tick runs, later results are ignored, and assert, finish and exit each cost one tick, observed from a second script.
- [ ] A run that ends without a result, or exhausts 600 ticks, fails with its own reason, and every run reports its tick count.
- [ ] WaitTillIdle is released exactly when every other thread has finished as observed at its position in the round-robin pass, in both orderings; two waiters never release each other; a stage with no objects never releases it. *(The last clause is unreachable; see D8's slice-6 amendment. The orderings are per object, and "two waiters" holds once both have started, as D8 now states; Codex PR 2 handover, round 2.)*
- [ ] Every one of the 215 cases matches its pinned class, the summary counts are pinned, and an expected failure that starts passing, or fails for any reason other than its pinned outcome, turns the suite red.
- [ ] No existing engine or app test changes, and `BrickKind`, `ProgramDocument` and the sample JSONs are byte-identical (`git diff --stat` on them is empty).

## Slices and test-first outline

Slices 2–5 are **risky** (program format, interpreter): `swift-code-reviewer` plus one Codex round each when green. Estimated at ~1,150 lines of non-test code. Four risky slices are a lot for one review, so this ships as **two PRs**: **PR 1 = slices 1–4** (fixtures and importer, ending with the import property) and **PR 2 = slices 5–7** (harness, WaitTillIdle, runner).

1. **Fixtures, manifest, catalog** (risky: no) — red: the catalog has 215 entries; every manifest entry has a fixture and vice versa; the hashes match; the versions are within D1's window or the case is pinned `unsupported(.version)`. Mutations: delete a fixture; flip a byte; drop a manifest entry.
   - *Green 2026-11-03 (`9786297`).* Red was all four non-parameterised tests failing on the missing manifest; the two parameterised ones had no cases, which `catalogHasAll215TestsOnce` exists to catch. **All 215 versions lie inside D1's window** (0.99995 … 1.13), so the window check is a plain assertion now and becomes the importer's constants in slice 4. The extraction is deterministic (a second run leaves the tree's hashes unchanged) and removes fixtures whose test is gone. 3.4 MB. **Mutants:** 7 tried, all killed: delete a fixture; flip a byte; drop a manifest entry; edit a version; a stray fixture; a wrong commit; a version below the window.
2. **XML tree and reference resolver** (risky: yes; D7) — red: elements, text and attributes; same-tag 1-based indexing; `..` chains; a fully qualified sibling not counted towards `brick[n]`; an unresolved reference → typed error; malformed XML → `malformed`, never a trap. Mutations: 0-based index; counting all siblings; ignoring `..`.
   - *Green 2026-11-03 (`2f1f400`), then reviewed: `swift-code-reviewer` + one Codex slice round.* Red was behavioural, on stubs. All 1120 references in the corpus resolve; a declaration may also point at a `userData` (user-defined bricks, out of scope). **Both reviewers found the same trap**: `brick[-9223372036854775808]` overflows `ordinal - 1`. That was a guard I had removed as an "equivalent mutant", having checked the equivalence only for representable ordinals. Fixed with a canonical ordinal grammar (digits only, no sign or leading zero). Also adopted from Codex, each mirroring XStream although none occurs in the corpus: `.` segments skipped; the `XmlFriendlyNameCoder` decoded on element names and reference strings (`__`, `_-`, `_.XXXX`); **forward references refused**, because XStream resolves against what it has unmarshalled, an earlier completed element or an ancestor. ## Codex brief review — what to attack

- D1: is "no format difference in the window" true for every element our importer reads, not just tag pairs (attribute names, `formulaList` category keys, `isUserDefined`, brick `commentedOut` vs older `isCommentedOut`)?
- D2/D5: does `interpretObject` on a boolean root (`TRUE()`, a comparison) produce `"true"` in Catroid, so that `1.0 == "true"` fails where our 1 = 1 passes? Is "first result wins" exact when two threads report in the same frame?
- D4: are the four contexts exhaustive (a brick root that takes a string, like `setThreadColor`; a comparison operand; a variable read of a stored string)?
- D6: is a failing assert's tick the one that ends the run, or does the frame finish first? Does the 600-tick budget match a 10 s wall clock at 60 fps closely enough, given Catroid's frame pacing?
- D7: is refusing name shadowing too strict for the runnable set? Is heading 90 the only start-pose difference (ADR-007's 0° = up)?
