# Variables

**Status**: Planned — 2026-10-19 | **Epic**: E8 (+ E3 formulas) | **Branch**: `feature/variables` (PR 1; later PRs get their own branches)

**Goal**: a program can make decisions and loop on conditions. Formulas gain comparisons, `and`/`or`/`not`, `true`/`false` and Catroid's `power()`; the control bricks If, If/Else, RepeatUntil, WaitUntil and ForVariableFromTo execute, preview and export as the Android Embroidery Designer does wherever Catroid is sound; and the user can author a simple condition in the app. Every divergence from Catroid is pinned by a named test.

**In scope**
- Formula logic: `= ≠ < ≤ > ≥`, `and`, `or`, `not`, the constants `true`/`false`, and `power()`.
- Control bricks: If…then, If…then…else, RepeatUntil, WaitUntil, ForVariableFromTo.
- ADR-008's block structure grows from opener/closer pairs to blocks with an optional middle marker (else); the editor verbs (ADR-045) follow.
- **US-323** from the backlog (decided 2026-10-19): a loop head reached mid-tick reads its formula a tick early. Every new condition goes through the same path, so it is fixed once, here.
- A **minimal condition editor** (decided 2026-10-19): one comparison of two number-or-variable operands.
- One bundled sample using For and If, checked in Ink/Stitch.

**Out of scope** (each deliberate)
- **Strings as values** (decided 2026-10-19, D1). They belong to the Language-test runner, whose equality ADR then only has to decide about strings.
- Lists and list bricks (ForItemInUserList), Catroid's `if_then_else` function, `rand`, Note.
- **Rename/delete of a variable declaration**: the known gap in ADR-045; it needs a program-wide rewrite verb and fits Project management.
- Project-scope declaration in the UI: with one object, project vs object scope cannot be seen.
- `AssertEquals`/`FinishStage`: the runner's. D1 settles their numeric equality now.
- `setVariable`'s failure value: ADR-018 says it writes 0 "mirroring Catroid data actions reading through interpretDouble", but current `SetVariableAction.kt:48` uses `interpretObject` and stores NaN. Filed to the backlog as US-326, not changed here.

**Brief review**: done 2026-10-19 — one Codex round, 8 findings (1 High, 5 Medium, 2 Low), all valid, all folded into this brief (journal). The High: blanket +0 canonicalization (D2) would erase the −0 Catroid keeps on negative underflow, and the planned operand table could not have caught it. Codex found no fault in D7, D8 or D11's tick paths.

## Decisions taken at planning (2026-10-19)

Planned with `swift-architect`. Four decisions taken by Sebastian on 2026-10-19: Double-only values (D1), the decimal128 divergence accepted and pinned (D6), the minimal condition editor (D16), US-323 pulled in (D11). Catroid paths below are relative to `catroid/src/main/java/org/catrobat/catroid/`.

- **D1 Value model: `Double` only.** Comparisons and logic return 1/0; `true`/`false` are 1 and 0. Catroid stores booleans in variables, but a read turns them into 1.0/0.0 (`formulaeditor/common/FormulaElementOperations.kt:91-104`), so nothing is lost numerically. **One equality rule**: `a` equals `b` iff `a == b` or both are NaN. It covers both places Catroid compares — the `=` operator (`equalsDoubleIEEE754` after a toString→toDouble round trip, `FormulaElementOperations.kt:64-76`) and `AssertEquals` (string-equal or `toDouble ==`, `content/actions/AssertAction.kt:45-51`) — which over Doubles reduce to this rule, including NaN = NaN and −0 = +0. Static scan of all 215 language tests: of the 56 using only Start scripts and no lists, string literals are mostly Note text, expected `"NaN"` (parses to NaN, the rule holds) or `"abc"` as a deliberately bad input (NaN in arithmetic). Genuinely string-dependent, and on the runner's expected-failure list: `testForLoopWithChangeVariableBrick`, `testJoin`, `testLetter`, `testLength`, `testRegex`. Rejected: a `number | string | bool` value — it changes `Variable.value`, the `[String: Double]` stores, every `interpretDouble` call site and ADR-037's finite policy, for no embroidery use.
- **D2 Comparisons mirror Java `Double.compareTo`** (`formulaeditor/FormulaElement.java:865-872`): NaN sorts above everything and equals itself (`NaN > 5`, `5 < NaN`, `NaN <= NaN` are 1); −0 sorts below +0. That breaks ADR-017's claim that zero-sign residue is "invisible to comparisons": `0 × −1 < 0` is 0 in Catroid (BigDecimal has no −0) and would be 1 here. **Fix: amend ADR-017 so the four decimal operators return +0 exactly where Catroid's decimal result is an exact zero** (`FormulaElement.java:820-855`): `plus`/`minus` whenever the result is zero (a `Double` sum is zero only by exact cancellation or zero operands, since addition cannot underflow); `mult` when either operand is zero; `divide` when the dividend is zero. **Negative underflow keeps its −0**: Catroid's DECIMAL128 product of two nonzero doubles is nonzero, and `doubleValue()` rounds a tiny negative to −0 (Codex brief review, finding 1; probed under JDK 17: `−MIN_VALUE / 2` and `−1e-300 × 1e-300` give −0, `−0 × 5` and `−0 + −0` give +0). Sign only, so no DST byte moves; every −0 Catroid itself produces (unary minus, literals, `ceil(−0.5)`, `min`, negative underflow) still matches. ADR-032 invariant 3: remove every copy of the old claim, including the `FormulaTests` case pinning `-0.0 × 5`. Fallback if the brief review objects: IEEE `<` with Java's NaN ordering, diverging only on Catroid's own −0.
- **D3 Logic.** `and`/`or` test `x ≠ 0.0` (IEEE), evaluate both sides and never return NaN: `NaN and 1` is 1, `0 and NaN` is 0 (`FormulaElement.java:873-876`). `not x` is `x == 0`, so `not NaN` is 0 (`:806-807`). `true`/`false` from `formulaeditor/function/MathFunctionProvider.java:55-56` via `Conversions.kt:31-32`.
- **D4 `power()` is not `^`.** It is raw `Math.pow` (`MathFunctionProvider.java:50`), without `^`'s NaN guard or zero canonicalization: `power(NaN, 0) = 1`, `power(−(0), −3) = −MAX` where `−(0) ^ −3 = +MAX`, `power(1, NaN) = NaN` (Java; C's `pow` gives 1). Each gets a named test. The brick-backend brief's reason for leaving it out ("`^` exists") was wrong; corrected there by this entry, not by editing it.
- **D5 Truthiness differs by brick — mirrored, each case pinned by name.** If/IfElse: `trunc32(x) ≠ 0` (`content/actions/IfLogicAction.kt:43`; both openers build that action independently — `content/bricks/IfLogicBeginBrick.java:192-212` and `content/bricks/IfThenLogicBeginBrick.java:155-169` — so each gets its own truthiness rows), i.e. our `interpretInteger ≠ 0` — `if 0.5` and `if −0.99` are false, `if MAX` is true. WaitUntil: the same rule (`formulaeditor/Formula.java:258-259`). RepeatUntil: `x ≠ 0.0` (`content/actions/RepeatUntilAction.kt:51`), so 0.5 exits the loop. NaN: If skips both branches (`IfLogicAction.kt:56-57`), RepeatUntil exits, WaitUntil keeps waiting (`content/actions/WaitUntilAction.java:66-69`).
- **D6 Decimal128 becomes structural — accepted and pinned** (decided 2026-10-19). ADR-017 accepted Double vs decimal128 for values; with `=` it now decides branches: `0.1 + 0.2 = 0.3` is 1 in Catroid and 0 here. ADR-019 class: a named test pins it, and the runner's `testFloatingPointArithmetic` is an expected failure.
- **D7 If/IfElse execution (ADR-018).** Compiled as `ifBegin(cond, falseTarget)`; `elseBranch` → a zero-tick jump to the end; `ifEnd` → a zero-tick marker. (a) An `ifBegin` reached after an action this tick yields before evaluating (the US-323 rule; Catroid evaluates on the If's own first `act`, one frame later). (b) The condition and the taken branch's first brick run in the same tick (`IfLogicAction.kt:51-63`). (c) **An If whose taken branch ran no action consumes the tick** — empty branch, NaN skip, a zero-count repeat inside: at `ifEnd`, if no action ran this tick, mark the tick acted and keep folding. Nested empty Ifs then cost one tick in total, as in Catroid, where libgdx `SequenceAction` advances one child per frame; yielding instead would add a tick per nesting level. Ticks: `[if true {move}, move]` = 2; `[if true {}, move]` = 2; `[move, if c {}, move]` = 3.
- **D8 RepeatUntil.** A loop opener closed by the existing `.loopEnd` (Catroid's loops share an end brick). The condition is checked before every iteration (0 iterations possible), again at body end in the same tick as the last brick (exit that tick if true), and again at the next iteration's entry in the next tick (`RepeatUntilAction.kt:60-79`). Both checks are visible across scripts, so both are mirrored; the loop needs per-thread "active" state (like `loopCounters`) to tell a first arrival (defer before evaluating) from a back-jump. **Pinned divergence**: Catroid re-checks validity every frame (`:61`), so a NaN mid-body aborts mid-body; we check only at iteration boundaries. Zero-iteration entry folds like an exhausted `repeatLoop` — ADR-018's existing one-tick difference, inherited.
- **D9 WaitUntil.** Action-producing like `wait`: each tick costs one poll; it completes in the tick it finds the condition true and emits `.waited`; the poll is deferred if the thread already acted this tick. **Pinned divergence**: Catroid's 0.02 s throttle (`WaitUntilAction.java:58-63`) polls every second frame at 60 fps, so its result depends on frame rate and there is no single behaviour to match; M2 already omitted loop delays. With one object and one script in the app, a WaitUntil is satisfied at once or never — a parity brick, and the brief says so.
- **D10 ForVariableFromTo** (`content/actions/ForVariableFromToAction.java:47-117`). On first arrival (deferred if the thread acted): `from` and `to` evaluated once with `interpretInteger` (truncate, saturate to Int32); if either throws, the loop is skipped and the variable untouched; `step = from ≤ to ? 1 : −1`; the variable is set to `from` in the same zero-tick step, so the first body brick sees it. The body always runs at least once (`from == to` runs once). At `loopEnd`, same tick: re-read the variable (body edits count), exit if `step > 0 ∧ v ≥ to` or `step < 0 ∧ v ≤ to`, else `v += step`. `to` is fixed at start (`testForVariableFromToBrick` asserts it); a non-integer `v` set in the body keeps stepping by ±1; re-entry from an outer loop re-initializes. **Non-finite and non-progressing values follow the directional exit check** (`ForVariableFromToAction.java:59-65`) and raw `Double` increment (`:117-119`), mirrored, with a table rather than a blanket rule (Codex brief review, finding 3): ascending, `v = −∞` never exits and `v = +∞` exits at once; descending, the reverse; `v = ±MAX` or `|v| ≥ 2^53` set in the body does not progress (`MAX − 1 == MAX`) and runs until the budget. Each row gets a named immediate-exit or budget-exhaustion test. The variable resolves like `setVariable` (object shadows project; unknown → object-local). **Name `""`**: Catroid writes a hidden dummy `UserVariable` (`content/bricks/ForVariableFromToBrick.java:163-168`) that no formula lookup can reach (`formulaeditor/UserDataWrapper.java:40-51`); a store key `""` would not be hidden, because our format round-trips `.variable("")` (Codex brief review, finding 2). So a loop with an empty name keeps its counter in per-thread loop state and never writes the store: `for "" from 1 to 1 { setY(variable("")) }` ends at y = 0, as in Catroid. A non-empty name resolves by name where Catroid binds an object identity; they differ only when an object and the project both declare the name and the Catroid program bound the project's — the same shadowing `setVariable` already has, noted for the importer, not tested here.
- **D11 US-323 as an ADR-018 amendment** (decided 2026-10-19). Any loop/If head without state, reached after an action this tick, yields before it evaluates. A script ending in such a loop finishes one tick later; verified that no golden's event timing moves (only `[…, repeat]` tails are affected).
- **D12 Block structure (ADR-008 amendment).** New `Brick` cases `ifThen(condition:)`, `ifElse(condition:)`, `elseBranch`, `ifEnd`, `repeatUntil(condition:)`, `waitUntil(condition:)`, `forVariableFromTo(name:from:to:)`. Two opener cases rather than one with an optional else: `BrickKind` stays a payload-free 1:1 mirror, the palette gets two entries, and the importer maps `IfThenLogicBeginBrick`/`IfLogicBeginBrick` one to one (Catroid's UI shows the same three rows, `content/bricks/IfLogicBeginBrick.java:47-48, 228`). Case names become coding keys and are permanent. `validate()` uses a kind-checked stack: loops close with `loopEnd`, Ifs with `ifEnd`; `elseBranch` exactly once, directly inside an `ifElse`, never inside an `ifThen`. New `ScriptValidationError` cases: mismatched end, misplaced/missing/duplicate else. `opensLoop`/`isLoopEnd` become block roles (opener/divider/closer); `matchingEnd`, `range(ofPairAt:)` and `matchingOpener` follow.
- **D13 Editor verbs (ADR-045 amendment).** Insert brings the whole template (`[ifElse, elseBranch, ifEnd]`); inserting `.elseBranch`/`.ifEnd` is rejected like `loopEnd`; delete at else or end redirects to the opener and removes the block **when a matching opener resolves, and otherwise deletes the marker as a leaf** — ADR-045's malformed-script rule (`EditorCore.swift:154-190`), with cases for a stray else, a stray if-end, a missing else and mismatched nested closers (Codex brief review, finding 4). Moving else or end is rejected. Insertion after an `elseBranch` means first in the else branch.
  **Accessibility moves** (Codex brief review, finding 5): the six actions in `Script+ListEditing.swift:67-150` generalize from "loop" to "block". Move Up/Down stop at an else (it is a boundary, not a sibling). The two move-out actions become **Move Above Block / Move Below Block**: the first block of a then-branch leaves above the opener, the last block of an else-branch (or of an `ifThen`'s body) leaves below the `ifEnd`. Crossing the else is a **new pair**, **Move Into Else Branch** (from the then-branch's last block: lands first in the else branch) and **Move Into Then Branch** (from the else branch's first block: lands last in the then branch), both defined for a leaf and for a whole nested block, with the post-removal destination stated as the existing helpers state theirs. The two move-into actions extend to an If above or below. `ListEditingTests`' reachability property must hold and must **observe** a crossing of the else in both directions, not just compare two transition graphs. The else row is indented at the opener's depth.
- **D14 File format.** Additive v1 under ADR-037's 2026-10-17 amendment; sample JSONs stay byte-identical; the new validation errors map to `.unbalancedScript`. `requiredFormatVersion` still not built.
- **D15 Variables.** Declare-on-use in object scope, value 0, as today. Catroid's `UserVariable.value` is `transient` and reset to 0 (`formulaeditor/UserVariable.java:35, 106-108`); our persisted `Variable.value` as an initial value is an extension the importer never fills.
- **D16 UI.** `FormulaText` renders operators with Catroid's precedence (`or` < `and` < comparison < additive); a comparison inside a comparison is always bracketed. `ReadOnlyFormulaReason.logic` for logic roots. **Condition editor** (decided 2026-10-19): `ParameterEditorKind.comparison(lhs, op, rhs)` when a condition slot holds `binary(comparison, leaf, leaf)` with number/variable leaves — an operator picker (six operators) and the existing number/variable controls on each side, all one undo session; anything else is locked. Defaults: condition `1 < 2` (`ui/fragment/CategoryBricksFactory.kt:361-380`); for-loop `from 1`, `to 10` (`common/BrickValues.java:93-94`). Palette order follows Catroid (`CategoryBricksFactory.kt:382-390`): wait, forever, ifElse, ifThen, waitUntil, repeat, repeatUntil, forVariableFromTo, setVariable, changeVariableBy.

**New ADRs**: **ADR-048** (logic and comparison semantics: D1–D6), **ADR-049** (control-brick execution: D7–D11). **Amendments**: ADR-008 (D12), ADR-017 (D2), ADR-018 (D11), ADR-040 (D16), ADR-045 (D13).

## Acceptance criteria

- [ ] Every new `Brick` and `Formula` case round-trips through `ProgramDocument` and is reflexively `==` — the existing case census, which fails to compile when a case is added.
- [ ] Every comparison and logic node matches a characterization table generated from Catroid's expressions under Java 17, including NaN, ±0 and ±MAX operands; `power` matches `Math.pow` and each D4 difference from `^` has a named test.
- [ ] The four decimal operators yield +0 exactly where Catroid's decimal result is an exact zero, and keep −0 on negative underflow; every −0 Catroid produces (unary minus, `ceil(−0.5)`, `min`, underflow) still does; no DST golden changes.
- [ ] Every divergence (D2 fallback if taken, D6, D8 mid-body NaN, D9 throttle, D10 `""` name) has a named test.
- [ ] Each control brick's truthiness follows D5, pinned per brick at 0.5, −0.99, −1, MAX and NaN.
- [ ] Each control brick's tick cost matches D7–D10 (the D7 tick table; nested empty Ifs cost one tick; a WaitUntil released by another script; RepeatUntil's two checks observed from a second script).
- [ ] The US-323 probe ends at (2, 3), and no existing golden's event timing moves.
- [ ] `validate()` accepts exactly the well-formed block structures — a property over generated scripts — and every editor verb keeps every script valid (`PairInvariantSoakTests`, `EditBalanceInvariantTests` over the new openers); accessibility moves still reach every arrangement a drag reaches.
- [ ] A condition of the form `leaf op leaf` is editable as one undoable session; any other condition is shown locked with its reason.
- [ ] Every palette kind, row sentence and new formula node has String Catalog entries.
- [ ] The new sample runs and exports, and its `.dst` opens correctly in Ink/Stitch (manual check).

## Slices and test-first outline

Every slice except 7 is **risky** → `swift-code-reviewer` + one Codex round when green.

1. **Formula logic** (risky: yes; D1–D6, ADR-017) — red: `FormulaCodableShapeTests` per new case; the census round-trip; the Java 17 characterization table (NaN, ±0, ±MAX, ±`leastNonzeroMagnitude` and ±smallest-normal operands for every comparison, logic and decimal-operator node); `power` vs `^` at NaN and −0; `0×−1 < 0 == 0`; `(−MIN/2) < 0 == 1` (underflow keeps −0); `(0/0) = (0/0) == 1`; `not NaN == 0`; `0.1+0.2 = 0.3 == 0` pinned under ADR-019; `FormulaText` rendering and lock reasons in the app. Mutations: IEEE `<` for compareTo; NaN ≠ NaN; `and` via trunc; `not` letting NaN through; `power` with `^`'s guards; canonicalization removed; canonicalization applied to every zero (kills underflow); `true`/`false` swapped; comparison brackets dropped.
2. **Block structure** (risky: yes; D12–D14, ADR-008/045) — adds only the If cases (`ifThen`, `ifElse`, `elseBranch`, `ifEnd`); `repeatUntil`, `waitUntil` and `forVariableFromTo` are added in the slice that executes them, so no merged PR exposes a brick without semantics (Codex brief review, finding 6). Red: a validation table (mismatched end, else outside/doubled/missing); insert/delete/move at else and end, including the malformed cases (stray else, stray if-end, missing else, mismatched nested closers → leaf delete); Move Above/Below Block and Move Into Else/Then Branch for a leaf and a nested block; indent; sibling and accessibility moves across else, plus reachability; `PairInvariantSoakTests` over the new openers. The interpreter compiles Ifs to an inert placeholder here, so this slice does not ship without slice 3. Mutations: a closer accepted for the wrong kind; a second else accepted; delete at else not redirected; else row indented at body depth; Move Into Else Branch landing below the `ifEnd`; leaf fallback dropped on a stray else; a reachability property that passes without ever crossing the else.
3. **If/IfElse execution** (risky: yes; D5, D7) — red: the truthiness table, separate rows for `ifThen` and `ifElse`; the D7 tick table; nested empty Ifs = 1 tick; a cross-script read timing; else only on false; `forever { if false {} }` costs one tick per iteration. Mutations: truthiness `≠ 0`; NaN taking the else branch; no deferral; no tick consumed when action-free; a tick per nesting level; the else jump yielding.
4. **US-323 + RepeatUntil** (risky: yes; D8, D11) — red: the US-323 probe ends at (2, 3); 0 iterations when true at entry; the end check in the same tick; the entry re-check next tick against a flag another script sets; 0.5 truthy; NaN exits; the mid-body NaN divergence pinned by name; existing goldens' event timing unchanged. Mutations: do-while order; entry-only check; trunc truthiness; NaN continuing; the US-323 fix reverted.
5. **WaitUntil** (risky: yes; D9) — red: completes in the tick it is true, next brick a tick later; deferred evaluation; NaN keeps waiting; 0.5 false; cross-script release. Mutations: completion not consuming the tick; evaluating while deferred; NaN completing.
6. **ForVariableFromTo** (risky: yes; D10) — red: 1.9→1 and −1.9→−1; descending; `from == to` runs once; the first body brick sees `from`; a body increment shortens the loop; `to` fixed; NaN bounds skip with the variable untouched; Int32 saturation; the ±∞/±MAX/2^53 direction table (immediate exit vs budget exhaustion, both directions); `for "" from 1 to 1 { setY(variable("")) }` ends at y = 0 and leaves the store without a `""` key; nested re-initialization; object vs project resolution; `testForVariableFromToBrick`'s cases rebuilt by hand. Mutations: pre-check (while) for post-check; `>` for `≥`; `step` from `<`; rounding for truncation; `to` re-read; the entry write dropped; increment before the check.
7. **Condition editor** (risky: no; D16, ADR-040) — `swift-ui-design` pass first. Red: the editor-kind mapping; one undo entry per session; picker writes; a non-comparison locked with its reason. Mutations: operator picker off by one; lhs/rhs swapped; a locked tree rewritten. Simulator screenshots.
8. **Sample** (risky: yes — checked-in program JSON; ADR-037, ADR-019) — a new `SampleID` using For and If, guarded by a JSON round-trip resource and an ADR-019 threshold screen. Mutation: a sample node changed while the resource stays. Exported and checked in Ink/Stitch.

## Codex brief review — what to attack

- D2: is canonicalizing zeros in the four arithmetic operators truly invisible outside comparisons (`arctan2`, `mod`'s divisor sign, `1/x`, sensors)? Does Android's `Double.toString` round-trip exactly for `=`?
- D7(c): does marking the tick acted at `ifEnd` match libgdx for an If at the end of a loop body and directly after a loop exit? Does it interact with ADR-018's empty-loop late tick?
- D8: the two-check order under concurrency; whether pinning the mid-body NaN divergence is acceptable.
- D9: the throttle divergence when another script releases the wait.
- D10: whether the variable write on first arrival, after the US-323 deferral, matches Catroid's frame; the `""` name; overflow to ±∞ in the variable.
- D11: golden timing shifts.
- D12/D13: validation completeness (else at the wrong depth); the reachability proof across else.
- D5: whether the per-brick truthiness split is fully cited, including `IfThenLogicBeginBrick` sharing `IfLogicAction`.
